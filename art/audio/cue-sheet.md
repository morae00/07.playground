## 0. 읽는 법

- **덱**: 음악은 덱 두 개(A·B)로 튼다. 한 덱은 base 버퍼 하나와 스템 버퍼들을 같은 시각에 시작한 묶음이다. 곡을 바꿀 때 두 덱을 교차 페이드한다.
- **마디 경계 맞춤(Q)**: "Q"라고 쓴 전환은 지금 덱의 다음 마디 경계에서 시작한다. 마디 길이는 곡 목록(§5.6 매니페스트)의 BPM·박자에서 계산한다. 기다림은 한 마디(최대 4초, 5장)를 넘지 않는다.
- **페이드**: 교차 페이드는 같은 힘(equal-power, sin/cos) 곡선이다. 들어오는 쪽만 있으면 0.0001에서 지수 램프(지금 앰비언스와 같은 방식)다.
- **dB**: 음악·앰비언스의 "−6 dB" 같은 값은 그 버스의 평소 수준에서 빼는 양이다(덕).
- **이어 듣기**: 같은 곡을 다시 틀 때, 멈춘 자리를 4마디 구간 시작으로 내려서 거기서 잇는다. 남은 길이가 8마디보다 짧으면 처음부터 튼다. 같은 곡의 처음을 스테이지마다 다시 듣는 피로를 줄인다.

## 1. 곡과 스템이 쓰이는 곳

| 곡 | 시작 조건 | 스템 |
|---|---|---|
| `menu` | 메뉴 화면, 프롤로그 | — |
| `ch1`~`ch5` | 캠페인 일반 스테이지(St1~4, 6~9), 무한 경쟁(화면에 보이는 장) | `-dense`: 적 밀도, 필드 보스, 흐린 사본, 무한 경쟁 라운드 보스 |
| `boss-mid` | 캠페인 St5에서 라운드 보스가 나올 때 | `-phase`: 페이즈 2 −6 dB, 페이즈 3·광폭화 0 dB |
| `boss-final` | 캠페인 St10에서 라운드 보스가 나올 때 | 위와 같음 |
| `enrage-sting` | 보스 스테이지의 첫 광폭화 단계 | — |
| `ending` | 5-10 첫 클리어의 5장 아웃트로 패널부터 엔딩 패널 끝까지 | — |

- 무한 경쟁은 보스 곡을 쓰지 않는다. 라운드 보스가 쉬지 않고(처치 2.4초 뒤) 다시 나오므로 보스 곡을 쓰면 무한 경쟁 전체가 보스 곡이 된다. 대신 장 곡의 `-dense`를 켠다.
- 필드 보스(일반 스테이지 36%·72%)와 흐린 사본(3장부터 55%)도 장 곡을 유지하고 `-dense`를 켠다. 보스 곡은 캠페인 라운드 보스(St5·St10)만의 것이다.

## 3. 전환 규칙 (공통)

1. **동시에 도는 덱은 둘까지.** 세 번째 전환이 오면 가장 오래된 덱을 0.1초에 끊는다.
2. **스템은 base와 같은 `when`으로 시작한다.** 짧은 스템은 `loop = true`로 반복하고, 이어 듣기로 base를 오프셋 `t`에서 시작하면 스템은 `t mod 스템 길이`에서 시작한다.
3. **스템 켜고 끄기는 Q, 1마디 램프.** 램프 중에 반대 요청이 오면 지금 값에서 반대로 램프한다.
4. **광폭화 스팅은 덱을 거치지 않는다.** 덕 노드 뒤, 음악 버스에 직접 연결해 자기 덕에 눌리지 않게 한다.
5. **덕은 겹치면 가장 깊은 값.** 일시정지(−8) 중에 드래프트(−4)가 열려도 −8.
6. **보스 곡의 페이즈 상태는 덱마다 기억한다.** 보스가 둘인 경우(캠페인에는 없음)를 대비해, 가장 높은 페이즈를 따른다.
7. **곡 디코딩 실패**: 무음으로 진행한다(효과음은 그대로). 합성 대체음은 없다. 실패는 오류 기록에 남긴다(TEC-14).

## 5. 제안: 버스와 믹스 규칙 (AUD-03)

### 5.1 음악 수준

지금 값(AUD-05 B안, 2026-10-12 적용, `docs/decisions/AUD-05-loudness.md` §5):

| 값 | 지금 | 뜻 |
|---|---:|---|
| `SYNTH_PEAK`(`audioPolicy.ts`) | 0.347 | 효과음 한 보이스의 피크 × 큐 음량 |
| `MUSIC_LEVEL`(`musicPlayer.ts:25`) | **0.32** | −16 LUFS 스테레오 곡이 기본 옵션에서 효과음 흐름보다 약 4 LU 아래에 앉는다 |
| `AMBIENCE_LEVELS`(`audioPolicy.ts`, 장별) | ch1 0.107, ch2 0.07, ch3 0.081, ch4 0.096, ch5 0.074(2026-10-27) | 앰비언스가 효과음 흐름보다 8~9.5 LU 아래 |
| 마스터 기본값(새 세이브) | 0.8 | 최종 출력 약 −27~−29 LUFS, 음악이 들어오면 약 1 LU 오른다 |

- 이 수준은 **모든 곡이 −16 LUFS로 납품된다는 가정** 위에 있다(`music-brief.md` §2.2). 그래서 곡마다 수준을 따로 두지 않는다.
- 곡이 들어오면 `npm run measure:mix`로 다시 잰다. 음악 버스가 효과음 흐름 −4 LU에서 많이 벗어나면 곡을 고치지 않고 `MUSIC_LEVEL`을 고친다(메인 세션).

### 5.2 앰비언스 수준

- 장별 수준은 §5.1 표(AUD-05 B안)다. 앰비언스 파일은 피크 0.9로 정규화되고, 이 수준으로 음악 버스 옆 앰비언스 버스에서 재생된다.
- 1장·4장 앰비언스 레시피를 바꾸면(점검 P2-3·P2-4, 보류 중) 그 장의 수준을 다시 잰다.

### 5.3 노드 구성

```
덱 A ─┐                                   ┌─ 스팅 소스 ─┐
덱 B ─┴→ 음악 덕 게인 → 일시정지 로우패스 ─┴────────────┴→ music 버스 → master → 리미터
앰비언스 소스 → 앰비언스 덕 게인 → ambience 버스 → master
```

- 덱 = base 소스 + 스템 소스들(각자 게인) → 덱 게인.
- 음악·스팅은 보이스 장부(`VoiceLedger`, 16보이스)에 넣지 않는다. 앰비언스처럼 따로 돈다.
- 일시정지 로우패스는 평소 20 kHz(사실상 통과), 일시정지 때 1.5 kHz로 0.3초 램프.
- 테이프 멈춤은 덱 base·스템 소스의 `playbackRate`를 함께 램프한다.
- 앰비언스 덕(−6, −9 dB)은 지금 `ambience()`에 수준 인자를 더하거나 덕 게인을 하나 둔다.

### 5.4 디코딩과 메모리

- `decodeAudioData`는 Float32 PCM으로 푼다. 48 kHz 스테레오 1분 ≈ **23 MB**. `ch1`(160초) ≈ 61 MB, 짧은 스템 16마디(40초) ≈ 15 MB.
- 제안: 지금 곡 + 다음 곡만 디코딩해 둔다. 교차 페이드가 끝나면 앞 곡 버퍼를 놓는다. `menu`는 메뉴에 있을 때만.
- 미리 읽기: 메뉴에서 장을 고를 때(아틀라스 팩과 같은 때), 무한 경쟁의 `nextLookChapter`(20초 전), 보스 스테이지 시작 때 보스 곡.
- 스템을 base와 같은 길이로 받으면 메모리가 두 배다. 브리프는 짧은 스템을 권했다(`music-brief.md` §2.10).
- `<audio>` 스트리밍(`MediaElementAudioSourceNode`)은 메모리는 적지만 루프 이음과 스템 동기가 샘플 단위로 보장되지 않는다. 덱 방식에는 버퍼를 권한다.

### 5.5 설치 크기 (TEC-05)

- Ogg Vorbis q6(약 190 kbps)는 1분에 약 1.4 MB다.
  - base 9곡 약 21.4분 ≈ 30 MB, 짧은 스템 7개 약 4.7분 ≈ 7 MB, 합 약 **37 MB**.
  - 설치 에셋 예산(경고 200 MiB) 안에 든다. `assets/packs/` 아래라 초기 에셋 예산(3 MiB)에는 잡히지 않는다.
- 마스터 WAV(48 kHz/24-bit, 약 450 MB)와 검수용 합 WAV(약 280 MB)는 `public/`과 git 밖에 둔다(`music-brief.md` §11 U6).
- `pack.json`이 생기면 빌드에 음악 코드가 실린다(`__MUSIC_PACK__`). 앱 JS 예산(TEC-05)은 그 커밋에서 메인 세션이 확인한다.

### 5.6 곡 목록(매니페스트) 제안

곡이 들어오면 sound-designer가 `public/assets/packs/music/pack.json`을 쓴다(텍스트, 자기 범위). 작곡가는 쓰지 않는다. 형식은 재생 코드의 `MusicPack`/`MusicTrackSpec`(`src/game/audio/musicPlayer.ts:7-19`)이다.

| 필드 | 뜻 | 재생 코드가 쓰나 |
|---|---|---|
| `file` | `base` 아래 파일 이름 | 쓴다 |
| `bpm`, `meter` | 템포와 마디마다 4분음표 박 수의 순환(4장 7/8은 3.5). 마디 경계(스템 켜고 끄기, 이어 듣기)를 계산한다 | 쓴다 |
| `loop` | 한 번만 재생하는 곡은 `false`. 없으면 루프 | 쓴다 |
| `cutAt` | 스팅을 끊는 시각(초). 보스 곡 덕이 여기까지 머물다 1.5초에 돌아온다. 없으면 3.6초 | 쓴다 |
| `stems.dense`, `stems.phase` | 스템 파일 | 쓴다 |
| `bars`, `samples` | 검수용 기록(마디 수, 마스터 샘플 수) | 읽지 않는다(무시) |

곡이 오면 채울 틀(스팅 `cutAt`은 납품 기록의 실제 값으로 바꾼다):

```json

 "tracks": {
  "menu": { "file": "menu.ogg", "bpm": 72, "meter": [4], "bars": 32, "samples": 5120000 },
  "ch1": { "file": "ch1.ogg", "bpm": 96, "meter": [4], "bars": 64, "samples": 7680000, "stems": { "dense": { "file": "ch1-dense.ogg" } } },
  "ch2": { "file": "ch2.ogg", "bpm": 80, "meter": [4], "bars": 48, "samples": 6912000, "stems": { "dense": { "file": "ch2-dense.ogg" } } },
  "ch3": { "file": "ch3.ogg", "bpm": 60, "meter": [2], "bars": 64, "samples": 6144000, "stems": { "dense": { "file": "ch3-dense.ogg" } } },
  "ch4": { "file": "ch4.ogg", "bpm": 120, "meter": [4, 4, 4, 3.5], "bars": 72, "samples": 6696000, "stems": { "dense": { "file": "ch4-dense.ogg" } } },
  "ch5": { "file": "ch5.ogg", "bpm": 60, "meter": [4], "bars": 36, "samples": 6912000, "stems": { "dense": { "file": "ch5-dense.ogg" } } },
```

## 6. 제안: 테스트

- **음악 지휘자를 순수 상태 기계로** 만든다(`VoiceLedger`처럼 Web Audio 없이). 입력: 앱 상태(§4 E5) + 엔진 이벤트 + 스냅샷. 출력: "덱 A에 `boss-final`을 마디 경계 t에", "스템 phase를 −6 dB로" 같은 명령. 단위 테스트로 이 문서의 표를 그대로 확인한다:
  - 보스 스테이지: 등장 → 보스 곡, 페이즈 2 → 스템 −6 dB, 광폭화 1단계에만 스팅, 처치 → 0.25초 페이드.
  - 무한 경쟁: 라운드 보스에 보스 곡이 나오지 않는다, 장 회전에 교차 페이드, 다음 장 미리 읽기.
  - 밀도: 0.55 위 2초 → 켬, 0.35 아래 6초 → 끔, 그 사이 흔들림에는 변화 없음.
  - 이어 듣기: 4마디 내림, 끝 8마디면 처음부터.
- **믹서 테스트**(`src/game/audio/mixer.test.ts`에 덧붙임): 덱 두 개 교차 페이드, 스템 같은 `when`, 스팅이 덕을 거치지 않음, 덱이 셋이 되면 가장 오래된 것을 끊음, 음악이 보이스 장부를 쓰지 않음.
- **UI 프로브**(`test:ui-probes`): 메뉴 → 1-1 시작 → 일시정지 → 재개 → 정산까지 음악 상태가 표대로 바뀌는지.
