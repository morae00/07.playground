# API — `k-characters.js` · `PN.characters` v1.0 (K8 · 캐릭터 7명)

단·노을·서리·독·휘·령·월의 64px 인게임 스프라이트와 HUD 초상을 그리는 SVG 문자열 생성기다. 결(結)은 `PN.heroKit`(`k-hero.js`)에 그대로 두고 이 모듈은 위임만 한다.
작업 지시서는 `docs/art/briefs/characters.md`(B2, §13 '검수 1차 정정' 포함)이고 납품서는 `docs/art/deliveries/K8-characters.md`다.

> **2차 납품 범위(완성판)**: 7명의 4상태 21프레임(idle 6 · run 8 · throw 4 · hurt 3)과 초상 6표정(calm · focus · hurt · lowhp · awakened · victory), 검수 1차 F1~F8 반영.
> 모르는 id·상태·표정을 부르면 **오류를 던진다**(자리표시를 돌려주지 않는다). death는 팀 결정대로 그리지 않으며 부르면 `unknown state` 오류다.

## 로드 순서
```html
<script src="kit/lib.js"></script>          <!-- PN.taper, PN.rng, PN.halftone, PN.speedLines -->
<script src="kit/k-hero.js"></script>       <!-- PN.heroKit, PN._hk -->
<script src="kit/k-characters.js"></script> <!-- PN.characters -->
```
- `PN._hk`는 **호출 시점에만** 읽는다(로드 시점에는 읽지 않는다). `k-hero.js`가 없으면 호출할 때 `Error('PN.characters: load k-hero.js before k-characters.js')`.
- `PN._hk`에서 쓰는 것(지시서 §2의 범용 도구): `Ctx`(호출마다 고유 id `hk<N>_`), `smooth`, `spriteRing`, `negate`(hurt f0·f1), `splat`(hurt 튐·초상 배경), `brushArc`(월 throw 속도 호, 초상 awakened 호, 휘 victory 획).
- 결의 생김새 함수(`head34`·`hat34`·`neck34`·`FACE`·`sHead`·`sCoat`·`sRibbon`·`sArm`·`sBody`·`scarf*`·`bandolier`·`spool`·`hand`)는 부르지 않는다. 결의 FACE 점열(`k-hero.js:176-178`)과 `edge()` 방식(`:199-215`)은 이 파일에 **복사**했다(`FACE0`, `edge`). `PN._hk`에는 아무것도 더하거나 고치지 않는다.
- 결과 문자열의 `<defs>`에는 본문이 실제로 참조하는 정의만 남긴다(`Ctx`가 만드는 블러 필터·안 쓰는 망점 패턴은 빠진다).

- 모르는 `id`·`state`·`expr`는 `throw new Error(...)`.
- **`'gyeol'` 위임**: `sprite('gyeol', …)` = `PN.heroKit.sprite(state, frame, opts)` 그대로, `portrait('gyeol', …)` = `PN.heroKit.portrait(expr, opts)` 그대로(id만 다르고 같은 문자열임을 확인했다). `mono`일 때만 이 모듈이 색을 먹 하나로 바꾸고(스프라이트는 白邊도 끈다), `hitbox`일 때만 오버레이를 덧붙인다.

### portrait opts
`frame`(true, 먹 테 6 + 종이 링 r 78.5 + 표정 테), `bg`(true, 표정 배경), `mono`(false).

|---|---|
| 로컬 박스 | 96 × 96 (1x px) |
| 피벗 | (48, 60) = 판정 원 중심, r 15 |

| 프레임 | idle 6 (8 fps) · run 8 (14 fps) · throw 4 (16 fps) · hurt 3 (12 fps) |

**리그**: 다리는 2뼈 IK(무릎 +x), run 다리 표·bob·찌그러짐은 결의 값(`k-hero.js:1481-1484`)을 인물별 보폭·bob 배율로 쓴다. 옷단은 다리보다 한 프레임 늦게 흔들린다(`:1487`). 땅에 닿는 옷자락(노을 장옷, 월 치마)의 단은 월드 좌표로 잡아 몸이 기울어도 바닥에 남는다. idle bob은 결의 −(1−cos)·0.5(독은 1.5배). 윗몸은 `translate(0 bob) rotate(lean 0 1)` 한 그룹이다.

### 3.1 throw 4 (draw → wind → snap → follow)
- 몸 기울기는 결의 표 [2, −2, 6, 5]°(`k-hero.js:1493`)에 인물의 idle 기울기를 더한다. 다리는 idle 자세다.
- snap의 투사체·잔획은 기울기 적용 뒤 채움 기준 x ≤ +44다(실측 최대: 휘 44, 단 43.5, 노을 43, 령 42.5).

### 3.2 hurt 3
- f0 · f1: `PN._hk.negate`로 먹 ↔ 종이 반전, 청록은 그대로. 몸 −9 / −6°, 모자·머리 장식 −14 / −10°(결과 같다, `k-hero.js:1493-1494`).
- f2: 원래 색, 몸 −3°, 장식 −5°, 몸에 먹 튐 5점(결의 좌표, `:1531`).
- 공통: 앞발이 앞으로 미끄러져 뒤꿈치로 선다.
- 인물별: 단 부채가 반쯤(45°) 접힌다 · 노을 고깔이 밑동을 축으로 뒤로 기운다(f0 −12°) · 서리 정자관이 기운다 · 독 단지 3개가 엇갈려 흔들린다 · 휘 붓이 기운다(장식 각의 0.6배) · 령 말총이 정수리 위로 앞으로 휘날린다(이때 종이 끈은 그리지 않는다: 머리 덩어리 안에서 끝나는 흰 획이 되므로) · 월 테가 기울고(0.8배) 쪽·비녀가 뒤로 흔들린다.
- 령의 A형 그림자는 반전 프레임에서도 띠로 읽히지 않는다(뒤로 내려가는 사선 경계, 검수 1차 F1).

## 9. 알려진 한계
- `aim`은 링만 돌린다(§2). 결은 팔도 돌리지만 굽기는 aim 0이라 게임 화면에는 차이가 없다.
- 외곽선 필터(결과 같음)는 사각 커널로 팽창한다. 대각선 방향으로는 원형 팽창보다 약 1.4배 더 나가서, 부품끼리 대각선으로 마주 보면 계산보다 가까워진다(단 idle 부채의 사북을 검수 값보다 1 오른쪽 (16.5, −12)에 둔 이유). 사선·톱니 가장자리의 계단도 같은 원인이고 사람 클린업이 필요하다.
- throw snap의 잔획 끝(채움 x ≤ 44)에 외곽선·白邊을 더하면 오른쪽으로 최대 x ≈ 47.75까지 칠해진다. 96 박스 안이고 굽기 칸 여유(+8) 안이다.
- 단의 상투·동곳, 월의 쪽 장식, 휘의 갈기 끝, 령의 말총은 초상 원 밖으로 대부분 잘린다(구도는 지시서 값). victory 반짝이는 결처럼 원 왼쪽 위에 있어 머리카락 뒤로 거의 가려진다.
- victory 소품(단 부채, 노을 손, 서리 책, 월 테)은 원 테에 일부가 가려진 채 아래에서 올라온다. 84 px에서 모양은 읽히지만 작다.
- 64px 얼굴·부채살·방울·시위·톱니는 줌 리샘플마다 화소가 달라진다. 사람 픽셀 클린업이 필요하다(바이블 §15).
