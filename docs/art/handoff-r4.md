# R4 아트·음악 작업 지시서

> 결정 기록 `docs/decisions/R3-decisions.md`의 D-14(킷 확장 전부), D-15(이야기 패널 6장 손그림), D-16(음악 9곡)을 외주나 다른 에이전트가 바로 작업할 수 있게 정리한 문서다. 납품물을 아래 위치에 두면 굽기 명령과 코드 연결은 이 저장소 쪽에서 한다. 스타일은 `docs/art/style-bible.md`(먹극화 · Paper Noir Ink), 세계관과 디자인 키워드는 `docs/lore/lore-bible.md` §4를 따른다.

## 0. 공통 규칙

- 신호색은 뜻이 정해져 있다(V2). 청록 = 플레이어와 아군, 산호 = 적의 위협(보스는 광폭화 때만), 호박 = 예고, 초록 = 보상, 보라 = 정예. 적 몸에 청록을, 아군 효과에 산호·호박·보라를 쓰지 않는다.
- 몸과 효과는 판정 원 안에 서야 한다(V4). 판정보다 크게 보이는 장식은 한눈에 장식으로 읽혀야 한다.
- 역할 실루엣은 챕터가 달라도 같다(V6). 흑백 32px로 줄여도 역할을 알아봐야 한다.
- 글자를 그림에 넣지 않는다. 화면 문구는 모두 문자열 표에 있다.

## 1. D-14 킷 확장

컨셉 킷(`art/concept-kit/`)은 SVG 문자열을 돌려주는 JS 모듈이다. 작업 방식은 `art/concept-kit/README.md`를 따른다: 에이전트 하나가 모듈 파일 하나를 자기 이름공간으로 쓰고, 함수마다 로컬 박스·피벗(판정 원 중심)·게임 표시 크기를 `API-<모듈>.md`에 적는다. 호출마다 내부 id가 겹치지 않게 접두사 카운터를 쓴다. 기존 모듈(`lib.js` 등 원본 코드)은 고치지 않는다.

### 1.1 2~5장 중간 보스 4종 — 새 모듈 `k-bosses3.js` → `PN.bossesC`

| 보스 | id | 패턴 | 칭호 · 키워드 (로어 바이블 §4.2) |
|---|---|---|---|
| 유리 주교 | `s2-mid-clones` | 분신 4체 소환 | 거울 설교의 주교. 스테인드글라스 주교관, 금 간 거울 얼굴, 장미창 제의, 거울 지팡이. 분신은 얼굴이 빛나지 않는다 |
| 무채 조수왕 | `s3-mid-tide` | 감속 웅덩이 5개 | 색을 씻는 조수왕. 익사한 메기 왕, 수문판 왕관, 물 번짐 도포, 우산처럼 편 삼지창 |
| 시계 폭군 | `s4-mid-clock` | 감속장 + 12발 링 | 멈춘 시간의 폭군. 등에 진 시계탑, 문자판 머리, 진자 대검 |
| 일식 원장 | `s5-mid-eclipse` | 오선지 7줄 탄벽, 한 줄 안전 | 일식 극장의 원장. 연미복, 일식 광배, 초승 가면, 지휘봉과 긴 자 |

- 호출 형식은 `PN.bossesB.draw(id, opts)`와 같게 한다(`API-bosses2.md`): 로컬 박스 384×384, 피벗 (192, 252), 판정 r108 로컬(게임 r54), 발 y 360, 오른쪽을 본다.
- 옵션: `phase` 1~3(2에서 균열, 3에서 코어 노출), `windup`(준비 자세 + 호박 '!'), `enraged`(먹 불꽃, 바깥 윤곽에만 산호 펄스), `detail` 'art' | 'game', `halo`, `shadow`, `mono`(단색 실루엣).
- 상태 12장(페이즈 3 × 대기·준비 × 평상·광폭화)이 아틀라스에 들어간다. 각 보스의 페이즈 2·3 무브 데이터가 이미 있다(`src/content/data/bossPhaseMoves.ts`): 무브의 예고 모양(원, 링, 레인, 격자, 원뿔)을 몸과 소품이 먼저 보여 주게 그린다.
- 같은 공격을 쓰는 쌍은 소품과 예고 도형으로 갈라 보이게 한다: 시계 폭군은 초침 집행관(필드 보스)과 같은 패턴이므로 대검·시계탑으로 구분한다.

### 1.2 필드 보스 5종 — 새 모듈 `k-bosses4.js` → `PN.fieldBosses`

| 보스 | id | 패턴 | 키워드 (로어 바이블 §4.1) |
|---|---|---|---|
| 균열 장교 | `field-shock` | 보스 자리 충격 지대 | 금 간 회벽 외투, 깨진 장교모, 반쯤 떨어진 회벽 가면, 군도를 바닥에 꽂는 준비 자세 |
| 백환 관리자 | `field-rings` | 22발 방사탄 | 굽은 등, 성유물함, 광배처럼 도는 쇠고리 3개 |
| 덫 설계자 | `field-trap` | 속박 덫 3개 | 청사진 망토, 곱자 팔, 컴퍼스 다리, 확대경 외눈 |
| 초침 집행관 | `field-clock` | 감속장 + 12발 링 | 두건 쓴 장신, 문자판 가면, 초침 도끼 |
| 무음 심판관 | `field-null` | 무음 지대 + 16발 | 검은 법복, 높은 법관 모자, 흰 실로 꿰맨 입, 의사봉 |

- 판정 원이 라운드 보스보다 작다: 게임 r38(라운드 보스 r54). 로컬 박스와 피벗은 bossesB와 같게 두고 판정 반지름만 r76 로컬로 문서화한다.
- 경량 세트로 충분하다: 대기·준비·공격·처치(R1 계획 §1.2). 페이즈 균열은 생략할 수 있다.
- 보스 바와 도감에 쓸 초상은 기존 보스 초상과 같은 방식으로 굽는다(얼굴 앵커만 알려 주면 된다).

### 1.3 보스 attack·death 포즈 — 기존 6종 + 위 9종

- 지금은 준비 자세와 처치 연출이 대신한다. 보스마다 `attack`(공격 순간 1장)과 `death`(쓰러짐 3~4장, 마지막 장은 먹 웅덩이)를 추가한다.
- 기존 6종(잉크 도살자, 종탑 간수, 용광의 입, 걸쇠 여제, 톱니 전령, 공백 천칭)은 `PN.bossesA`·`PN.bossesB`에 옵션 `pose: 'attack' | 'death'`, `frame`으로 붙이는 형태를 권장한다. 기존 모듈을 고쳐야 하므로 같은 작업자가 맡는 편이 좋다.

### 1.4 스킬 VFX 17종 — 새 모듈 `k-skills-vfx.js` → `PN.skillVfx`

- 대상: `src/game/skillNumbers.ts`의 스킬 17종과 각성 변형. 판정 크기(반지름, 길이, 폭)는 `src/content/data/skillNumbers.ts`에 레벨별로 있다. 그림은 그 판정 모양을 그대로 보여 줘야 한다.
- 색은 청록·먹·흰 계열만(owner=player). 감소 모션에서도 판정 모양은 그대로 보인다(V4).
- 스킬마다 필요한 것: 발사체 또는 장판의 시작·지속·사라짐 프레임, 각성 변형, 패시브는 발동 오라와 아이콘 팝. 17종 전부가 대상이다. 지금은 렌더러가 대부분 벡터 도형으로 그린다(바늘의 타격 별과 처치 연출만 킷에서 구웠다).
- 호출 형식 제안: `PN.skillVfx.draw(skillId, stage, { awakened, frame, radius })` → 반지름에 맞춰 그리는 SVG.

### 1.5 큰 칸막이 윗면 — `k-env.js` 보정

- 5개 장의 막는 소품(solid) 중 큰 두 크기 200×130과 280×190은 윗면이 빈 돌 받침처럼 보인다. 장별 윗면 장식(난간, 철책, 둑 위 갈대, 문자판 받침, 흑요석 결)을 넣는다. 발자국(판정 사각형)은 바꾸지 않는다(`src/game/obstacleCatalogue.ts`와 같아야 한다).

### 1.6 굽기와 확인 (저장소 쪽)

```
node scripts/build-atlas.mjs        # 챕터 팩(public/assets/packs/chapter-0N/)과 아틀라스 매니페스트
node scripts/build-ui-art.mjs       # 초상·도감 시트와 이야기 패널
npm run test:unit                   # 굽기 사양과 엔진 발자국 일치, 시트 칸 검사
npm run test:visual                 # 화면 검사 144장
```

- 새 보스는 `art/atlas-spec.mjs`의 `BOSS_SPRITES`, `src/game/render/assets/slots.ts`의 `BOSS_SLOTS`, `art/ui-art-spec.mjs`의 `BOSS_PORTRAITS`에 등록해야 화면에 나온다. 이 등록과 attack·death·스킬 VFX를 쓰는 렌더러 코드는 저장소 쪽에서 한다.
- 굽기 검사는 셀 가장자리에 닿는 그림, 빈 그림, 같은 속성이 두 번 나오는 태그를 실패로 잡는다.

## 2. D-15 이야기 패널 6장 (손그림)

- 대상: `prologue-1`~`prologue-4`, `ending-2`(마지막 바늘로 경계를 꿰맴), `ending-4`(지워진 이름들과 스승의 이름이 돌아옴). 팀이 엔딩 두 장을 바꿔도 된다.
- 장면 내용과 문구: `public/assets/content/story.json`의 각 패널 `lines`·`quote`, 로어 바이블 §7.
- 형식: 1200×675 px, 16:9, WebP(품질 0.85 안팎) 또는 PNG(저장소 쪽에서 WebP로 바꾼다). 그림 안에 글자를 넣지 않는다. 문구는 그림 아래 대화상자에 따로 나온다.
- 위치: `public/assets/packs/story/<id>.webp`를 같은 이름으로 덮어쓴다. 코드는 고칠 필요가 없다. 손그림을 넣은 패널은 `art/ui-art-spec.mjs`의 `STORY_PANELS`에서 빼야 다음 굽기가 덮어쓰지 않는다(저장소 쪽에서 한다).
- 지금 임시본(킷 조합)이 같은 자리에 있으니 구도 참고로 쓸 수 있다.

## 3. D-16 음악 9곡

| 곡 | 쓰이는 곳 | 길이·형태 |
|---|---|---|
| 메뉴 | 메뉴 화면 | 1.5~2분 루프 |
| 1장 먹선 골목 ~ 5장 일식 관문 (5곡) | 장별 일반 스테이지. 무한 경쟁은 장이 바뀔 때 곡도 바뀐다 | 2~3분 루프. 장의 재질(회벽·종이, 철·스테인드, 물·석재, 톱니·황동, 흑요석·일식)을 소리에 담는다 |
| 보스 2곡 | 중간 보스 공통, 장 최종 보스 공통 | 2분 루프. 광폭화 스팅 1개(3~5초)를 따로 |
| 엔딩 | 엔딩 이야기 패널 | 1.5~2분, 루프 없음 |

- 형식: Ogg Vorbis(또는 Opus) 48 kHz 스테레오, 마스터 WAV도 함께. 루프 곡은 이음매 없이 끝이 처음으로 이어져야 한다.
- 라우드니스: 통합 −16 LUFS, 트루 피크 −1 dBTP(AUD-03 기준). 효과음과 겹쳐도 경고음(텔레그래프)이 묻히지 않게 2~4 kHz 대역을 비워 둔다.
- 장별 앰비언스(합성 v0)가 이미 깔리므로 음악이 그 위에서 어울려야 한다(`ambience.ch1~5`).
- 위치: `public/assets/packs/music/` (파일 이름은 `menu`, `ch1`~`ch5`, `boss-mid`, `boss-final`, `enrage-sting`, `ending`). 음악 재생 코드(곡 전환, 페이드, 광폭화 스팅)는 곡이 들어오면 저장소 쪽에서 만든다(AUD-03).
- 선택: 전투 강도에 따라 겹치는 스템 2단(적 밀도, 보스 페이즈)을 주면 동적 레이어로 쓸 수 있다. 없으면 단일 루프로 쓴다.
