### 0.1 확인한 사실 (코드·렌더로 확인)

- 분신은 보통 중형 적이다. 접근형이면 charger 역할이고, 낮은 확률로 원거리 shooter가 된다(`:2830-2835`).

**P2·P3 무브는 데이터만 있고 아직 돌지 않는다**
- 근거: `docs/ARCHITECTURE.md:238`. 무브에 `name` 키도 없다.
- 지금은 P2·P3에서 기본 패턴이 빨라질 뿐이고, 페이즈 내레이션도 그렇게 말한다(`public/assets/content/story.json:195-222`).
- 따라서 준비·공격 포즈를 페이즈와 따로 고를 수 있어야 한다(§1.4의 `move`).

**굽기와 초상**
- 굽기 호출은 `PN.<module>.draw(kit, { phase, windup, enraged, ...options })`이고, 앵커는 발이다(`art/atlas-spec.mjs:77-121`). bossesB 묶음은 박스 384, 앵커 (192,360), 0.5배, `{ detail: 'game', shadow: false }`로 굽는다.
- 보스 초상은 **game 디테일 전신**을 얼굴 앵커 근처에서 원으로 잘라 만든다(`scripts/build-ui-art.mjs:125-135`, `art/ui-art-spec.mjs:35-42`). game 얼굴이 약 1.4배로 커져도 버텨야 한다.

**리뷰 스크립트**
- 리뷰 스크립트는 모든 `k-*.js`를 한 페이지에 읽는다(`scripts/art-review-sheet.mjs:30-31`). 새 모듈에 오류가 있으면 다른 작업자의 렌더도 실패한다.
- 이 지시서의 검사 명령 틀은 기존 모듈로 미리 돌려 봤다: 22상태 격자 + `--check`, 발을 맞춘 48px 단색 줄, 회색 변환, getBBox 표. 모두 동작했다.

## 1. 공통 사양 (네 보스 모두)

### 1.1 모듈 규칙

1. **구조.** IIFE로 쓰고, 마지막에 다음 객체를 만든다. 다른 이름공간은 건드리지 않는다.
   `PN.bossesC = { K, BOX, CH, META, ids, draw, anchors, parts, anchorsOf, _ }`
2. **자기완결.** `k-bosses2.js`에서 다음을 **복사해** `PN.bossesC._`에 둔다.
   - `ctx`(:28-58)
   - 도우미(:92-188): `gearPath, circ, ell, smooth, rotP, drip, crack, pcrack, flame, exclaim, chain, dry`. 눈 함수는 §1.10대로 새로 쓴다.
   - 조합기 `filters`·`draw`·`anchors`(:845-937)
   - 앵커는 bossesB와 같은 이름을 쓴다.
3. **id.** 호출마다 접두사 카운터 `kb3_<n>_`를 붙인다. 패턴·clipPath·mask·filter·`<g id>`가 모두 대상이다. 같은 식을 두 번 불러도 id가 겹치면 안 된다(`--check`가 잡는다).
4. **늘 읽히는 파일로 둔다.** 저장할 때마다 `node scripts/art-review-sheet.mjs bosses --check`가 kit error 없이 도는지 본다. 기준선은 18건 ok다.
5. **금지**
   - 한 태그에 같은 속성 두 번. `X.P(d, fill, v, extra)`의 extra에 `stroke-linejoin`을 다시 쓰지 않는다.
   - 그림 안 글자. 문자판 숫자, 자 눈금 숫자, 소리 글자를 모두 막는다. 눈금은 선으로 그린다.
   - `<image>`, 외부 참조, 블러. 헤일로·펄스용 morphology는 허용한다.
6. **방향.** 몸은 자전하지 않고 오른쪽(3/4 정면)을 본다. 반전은 호출부가 한다.

### 1.3 호출 형식과 옵션

`PN.bossesC.draw(id, opts) → string`은 `<g class="kb3 kb3-{id}">`와 그 호출의 `<defs>`를 돌려준다.

| opt | 기본 | 뜻 |
|---|---|---|
| `phase` | 1 | 파손 층만 정한다. 1, 2(종이 균열 + 페이즈 표식), 3(블랙 스팟 흘러내림 + 코어 노출). 포즈와 따로다 |
| `windup` | false | `pose:'idle'`일 때 준비 자세 + 호박 '!'를 그린다 |
| `pose` | 'idle' | 'idle' \| 'attack' \| 'death'. attack은 그 무브의 공격 순간 1장이다('!' 없음, windup 무시). death는 `frame`을 쓴다 |
| `frame` | 0 | death 0~3. 3이 먹 웅덩이다. 범위 밖 값은 잘라 쓴다 |
| `move` | 페이즈별 | 'base' \| 'p2' \| 'p3'. 준비·공격 포즈가 어느 무브의 것인지 정한다. 기본값은 phase 1→'base', 2→'p2', 3→'p3' |
| `enraged` | false | 먹 불꽃(검은 불 + 종이 심), 백열 눈, 바깥 윤곽에만 산호 펄스 2px(먹 링 샌드위치) |
| `clone` | false | 유리 주교 전용 유리 분신 미끼(§2.1). 다른 id에서는 무시한다 |
| `detail` | 'art' | 'art' \| 'game'. game은 외곽 ×2.5, 내부선 ×1.8, 망점 피치 6(3px)이고 작은 디테일을 뺀다 |
| `halo` | 장 base | 녹아웃 헤일로 색. 2장 #ABADB4, 3장 #ADB4AA, 4장 #BBAE94, 5장 #ABA5AC. false면 끈다 |
| `mono`, `monoColor` | false, ink | 단색 실루엣. `front` 층('!', 포즈 FX)은 뺀다 |
| `shadow` | true | 발밑 그림자 |
| `hitbox` | false | 점선 r108 @pivot + pivot 십자 + feet 점(bossesB와 같다) |

- death는 `phase`·`windup`·`enraged`·`move`·`clone`을 무시하고 P3 파손 상태에서 시작한다.
- 모르는 id는 bossesB처럼 주석만 든 빈 `<g>`를 돌려준다.
- 함께 내보낼 것
  - `PN.bossesC.ids = ['bishop','tide-king','tyrant','director']`
  - `CH = { bishop:'ch2', 'tide-king':'ch3', tyrant:'ch4', director:'ch5' }`
  - `META[id] = { gameId, chapter, stage: 5, pattern, moves: { p2, p3 }, portrait: { center, scale } }`

### 1.4 상태와 무브

- **그릴 것(보스마다):** 대기 1벌, 준비 3벌(base·p2·p3), 공격 3벌(base·p2·p3), 처치 4장. 페이즈 파손과 광폭은 이 위에 얹는 층이다.
- **준비와 공격은 한 동작의 두 극점이다.**
  - 준비는 예비 동작의 최대치다. 공격보다 먼저, 더 크게 설계한다(바이블 §10.2-3, `:259-268`).
  - 공격은 동작이 끝난 자세(팔로스루)다.
  - 둘 다 같은 팔·소품 리그 수치에서 만든다. 권장 구조: `POSES[id] = { idle, windup:{base,p2,p3}, attack:{base,p2,p3}, death:[f0..f3] }`
- **예고 모양 단서.** handoff §1.1은 "무브의 예고 모양을 몸과 소품이 먼저 보여 주게" 그리라고 한다. 준비 자세의 소품 모양이 그 무브의 `telegraph.shape`를 닮게 한다.
- **개수 단서.** 기본 패턴은 개수가 확정이므로 몸 단서의 개수를 맞춘다. 주교 **4**, 조수왕 **5**, 폭군 **12**, 원장 **7줄 중 1줄 비움**.
- **포즈 FX(광선, 물줄기, 소리 호, 날아가는 파편)는 모양 단서다. 방향 단서가 아니다.** 실제 방향은 지면 예고가 맡는다. 그래서:
  - 소품에서 80 로컬 이내로 짧게 그린다.
  - 먹·종이만 쓴다.
  - **사선 해칭은 쓰지 않는다.** 해칭은 지면 예고 전용이다(바이블 §6-5).
  - 산호·호박도 쓰지 않는다('!'만 예외).
  - `front` 층에, 지면 위 FX는 `under` 층에 둔다.
- **`move`와 `phase`를 섞어도 깨지지 않아야 한다.** 지금은 P2·P3 무브가 돌지 않으므로 메인 세션이 phase 2·3을 `move:'base'`로 구울 수 있어야 한다(예: phase 3 + move 'base').

### 1.10 얼굴 공통 규칙: 입체파 얼굴을 피하는 법

**반례(렌더로 확인).** 결 초상 calm(`node scripts/art-review-sheet.mjs hero-portrait --scale 3`)은 옆얼굴 윤곽 위에 3/4 눈 배치가 얹혀 시점이 섞이고, 챙 그림자가 형태와 무관한 직선으로 얼굴을 자른다(R4-faces §1·§2.1). 기존 보스에서도 같은 종류가 보였다:
- 전령: 문자판 눈의 비율(0.84)이 나팔 종구 평면(0.69)과 달라 붙여 넣은 원처럼 보인다.
- 천칭: 눈이 반쯤만 눕혀져 있다.
- 여제: 치비풍 하이라이트 눈이다.
- 5장 일식 눈: 가운데 코어라 "8"이나 고글로 읽힌다.
- (R4-faces §2.6·§2.7)

네 보스는 아래 규칙을 지킨다.

1. **각도는 하나다.** 보스마다 머리 yaw(오른쪽 +)를 하나 정하고 몸도 같은 3/4로 짠다. 주교 30°, 조수왕 25°(입체 머리), 폭군 30°, 원장 35°. 다른 각도의 요소를 붙이지 않는다.
2. **평면 가면은 면 좌표계 하나에 그린다.** 주교 거울, 폭군 문자판, 원장 초승 가면이 해당한다.
   ```js
   // _.plane: 가면 로컬(정면, 원점 = 가면 중심)에서 그린 요소를 감쌀 변환 하나
   _.plane = (c, yaw, roll = 0) => `translate(${f(c[0])},${f(c[1])}) rotate(${roll}) scale(${f(Math.cos(yaw * Math.PI / 180))},1)`;
   // 판 두께 띠의 화면 폭 = depth × sin(yaw). 왼쪽(먼 쪽) 가장자리에만 그린다
   _.planeEdge = (depth, yaw) => depth * Math.sin(yaw * Math.PI / 180);
   ```
   - 테(베젤)와 그 안의 눈·균열·눈금·바늘을 **모두 한 `<g transform>` 안**에 그린다. 안쪽 요소에 따로 scale을 걸지 않는다(전령 0.84/0.69 어긋남의 원인).
   - 오른쪽을 보는 판의 두께는 **왼쪽에만** 보인다. 계산: 판 왼쪽 가장자리의 바깥 법선 (−1,0,0)이 yaw만큼 돌면 관객 쪽(z+) 성분이 생긴다. 오른쪽에 두께 띠를 그리지 않는다.
3. **입체 머리(조수왕)는 타원체 도우미 하나로 좌표를 얻는다.**
   ```js
   // _.wrap: c 머리 중심, rx·ry 화면 반지름, yaw 오른쪽 +(도), tilt 내려다보는 각(도)
   _.wrap = (c, rx, ry, yaw, tilt) => (lon, lat) => {   // lon: 얼굴 정중선 기준 경도, lat: 위도(위 +), 도
     const R = Math.PI / 180, a = (lon + yaw) * R, b = lat * R, t = tilt * R;
     const z = Math.cos(a) * Math.cos(b);
     return {
       x: c[0] + rx * Math.sin(a) * Math.cos(b),
       y: c[1] - ry * (Math.sin(b) * Math.cos(t) - z * Math.sin(t)),
       sx: Math.max(0, Math.cos(a)),            // 가로 단축(먼 쪽 요소를 이만큼 누른다)
       sy: Math.max(0.3, Math.cos(b - t)),      // 세로 단축(근사)
       visible: Math.sin(b) * Math.sin(t) + z * Math.cos(t) > 0.02,
     };
   };
   ```
   - 눈·입·수염 뿌리·콧구멍·왕관 띠·명부 경계를 모두 여기서 얻는다.
   - 먼 쪽 요소는 `sx`만큼 가로로 눌리고 머리 윤곽 쪽으로 붙는다. **크기만 줄인 정면 원을 먼 눈으로 쓰지 않는다.**
   - 가로로 도는 선(눈선, 입선, 왕관 띠)은 위에서 내려다보므로 아래로 휜 호가 된다. 수평 직선으로 긋지 않는다.
   - `visible`이 false인 곳으로 가는 선은 머리 윤곽에서 끊는다. 먼 입꼬리와 먼 수염 뿌리는 윤곽 뒤에서 나온다.
4. **그림자는 덩어리 하나 + 액센트 하나다.** 키 라이트는 좌상단이다. 그림자는 다음 둘 중 하나다.
   - (a) 위의 차양(주교관 띠, 크라운 베젤)이 얼굴에 떨어뜨린 초승달
   - (b) 입체 머리의 우하단 터미네이터. 만드는 법: 머리 타원에서 같은 타원을 좌상단으로 0.25r 민 것을 뺀다.

   경계는 형태를 따른 곡선이다. 금지: 얼굴을 가로지르는 각진 다각형, **두 눈을 가로지르는 수평 띠**(바이블 §9의 주인공 규칙을 보스에도 쓴다, §7 Q6). 액센트는 반사 한 획이나 명부 한 조각이다.
5. **선 위계를 지킨다.**
   - 얼굴 테가 가장 굵다: art 4~5, game 7~8 로컬.
   - 이목구비(눈 테, 큰 균열, 입선, 바늘): art 1.8~2.4, game 3.6~4.4.
   - 질감(눈금, 잔 균열, 결): art 0.8~1.2. game에서는 빼거나 3.6 이상으로.
   - 균열과 수염은 뿌리를 굵게, 끝을 가늘게(`PN.taper` 'start'). 입선은 'mid'.
6. **명도와 눈.**
   - 얼굴은 큰 밝은 면 하나이고, 그 안의 눈빛이 가장 밝은 점이다. 종이 면 위의 종이 점은 보이지 않으므로 먹 소켓(먹 테, 먹 별)으로 감싼다.
   - 두 동공은 모두 플레이어 쪽(+x)을 본다. 용광의 입의 사시 같은 실수를 피한다.
   - 하이라이트 점을 눈마다 덧붙이지 않는다(R4-faces Q5: 하드보일드 톤).
7. **세 크기에서 각각 본다.**
   - game 1x: 테, 종이 면, 눈빛 점
   - 초상 1.4배: 위의 것 + 그림자 덩어리
   - art 6배: 위의 것 + 두께 띠, 균열 갈래, 눈금

### 1.11 포즈 공통 규칙

- **준비.** 대기와 실루엣이 48px 단색에서도 다르게 읽혀야 한다. 팔과 소품의 각도를 크게 바꾼다. '!'는 `exclaim`(먹 + 호박 + 종이 심)으로 그리고, 얼굴·소품과 겹치지 않는 머리 위 빈 곳에 둔다. 그 자리를 `head` 앵커로 보고한다.
- **공격.** '!'는 없다. 소품이 끝까지 간 자세에 짧은 방출 FX를 더한다(§1.4). 몸 기울기와 옷자락이 따라온다.
- **처치 4장**(handoff §1.3, 바이블 §6-10)
  1. f0 피격: 눈빛이 꺼지고 가면이 깨진다. 실루엣은 대기와 비슷하게 둔다.
  2. f1 무너짐: 키가 약 70%로 줄고, 소품이 떨어지고, 머리 장식이 기운다.
  3. f2 녹아내림: 키가 약 40%로 줄고, 먹이 아래로 흐른다. art에는 종이 조각 2~3개를 둔다(원고 종이가 드러남, v1.0 §10.4 `:422-423`).
  4. f3 먹 웅덩이: 지면 타원 중심 (192,346), rx 120~140, ry 30~40. ink700 젖은 면에 ink 테, art에서는 ink300 비백 조각을 더한다.
  - f3에는 **얼굴 유물 하나**를 웅덩이에 눕히고, 그 눈을 종이 ✕(먹테)로 바꾼다. 적 처치 데칼의 ✕✕ 문법이다(`PN.vfx.decal(0, …)`, 렌더로 확인).
  - f3에서는 y 300 위로 솟는 것이 없어야 한다. 누운 소품 끝은 30 이내로 예외를 둔다.
  - 처치 프레임에 산호·호박을 쓰지 않는다.
- **페이즈 층**(바이블 §10.2-4)

## 2. 보스별 지시

### 2.1 유리 주교 `'bishop'` (s2-mid-clones · 2장 St5)

**칭호와 키워드를 형태로 옮긴다.** 거울로 설교하는 주교다. 신도의 얼굴을 거울에 옮겨 담고 원래 얼굴을 지웠다. 그래서 얼굴은 금 간 거울이고(로어 §3.1의 지워진 얼굴 자리, `docs/lore/lore-bible.md:102-105`), 무기도 거울 지팡이다. 스테인드글라스 주교관과 장미창 제의를 입는다.

**48px 단색 실루엣**
- 가장 가늘고 높은 기둥이다.
- 꼭대기에 두 봉우리로 갈라진 높은 주교관이 있다.
- 오른쪽에 몸과 나란한 **수직** 지팡이가 서 있고 그 끝에 타원 거울이 있다.
- 하단은 거의 곧게 떨어지는 긴 코프다(밑단 폭 ≤ 170).
- 구별: 간수(범종 머리, 대각 지팡이), 여제(종 치마 + 부채), 천칭(T자 대), 백환 관리자(굽은 등 + 성유물함)와 겹치지 않는다.

**얼굴(초승 가면, 한 눈)**
- **구조.** 평면 판 하나, yaw 35°, roll −6°. `_.plane((216,94), 35, -6)`(가로 0.82)로 감싼다.
  - 가면 로컬 모양 = 바깥 원(중심 (0,0), r28) − 안쪽 원(중심 (−18,−1), r22).
  - 그러면 볼록한 등이 플레이어 쪽(오른쪽)을 향하는 ☽ 모양이 된다. 뿔 끝은 약 (−16,−23)(눈썹)과 (−18.5,21)(턱), 높이 약 44, 눈선에서 두께 약 24.
  - 판 두께 띠는 **안쪽(오목, 왼쪽) 가장자리에만** 둔다: ink500, `planeEdge(6,35)` = 3.4.
  - 테: 먹, art 3 / game 5.
- **눈 하나 = 5장 일식 고리 눈.** 가면 로컬 (13,−2)에 둔다.
  - paper50 원판: 반지름 art 6 / game 7
  - 먹 코어: 반지름 ×0.74. **+x로 r×0.2 치우쳐** 왼쪽에 종이 초승 테가 남게 한다(R4-faces E1: 가운데 코어는 고글·도넛으로 읽힌다)
  - 덧붙인 하이라이트 점은 없다
- **나머지 얼굴은 먹(일식에 먹힌 쪽)이다.** art에서만 턱 윤곽 ink300 가는 선 하나를 둔다. 두 번째 눈, 코, 입은 그리지 않는다.
- **그림자.** 바깥 호를 따라 오른쪽 아래 가장자리에 20% 망점 띠 하나(폭 5, art만). game은 평면 종이 + 테다.
- **액센트.** 윗뿔 끝의 작은 paper50 반사(art만).

**페이즈와 광폭**
- **P2 표식.** 자의 앞 끝이 계단식으로 부러진다(그 자리에 `pcrack`). 연미복 등과 꼬리 뿌리에 `pcrack`. 가면 아랫뿔에는 가는 먹 금 하나(눈에서 멀리).
- **P3.**
  - 연미복 앞이 찢겨 코어가 드러난다: 먹 구슬(r11) + 둘레에 paper300 짧은 빛살 6개. 고리 모양 코로나는 금지다(눈과 같은 도형이 된다).
  - 꼬리 하나가 짧게 찢긴다. 광배 오른쪽 아래가 투명하게 한 입 지워진다(5장 구멍).
  - 방울 4개.
- **광폭.** 광배 윗테에 불꽃 5개, 지휘봉 끝에 1개. 일식 눈이 백열이 되어 코어가 paper50으로 바뀐다.

**처치**
1. f0: 가면이 둘로 갈라지고 눈이 꺼진다(코어 먹, 테 ink300). 코로나가 호 3조각으로 끊기고 지휘봉이 부러진다.
2. f1: 커튼콜 인사처럼 앞으로 숙이며 무너진다(70%). 광배가 뒤로 가라앉는다.
3. f2: 몸이 녹고 광배 아래로 먹이 흘러내린다(녹는 검은 해). 꼬리가 고인다.
4. f3: 둥근 먹 웅덩이(rx 120, ry 36). 뒤 가장자리에 paper300 가는 선이 남아 웅덩이의 코로나가 된다. 두 쪽 난 가면(눈 자리는 종이 ✕), 가로놓인 자, 지휘봉 두 토막.

**추가 앵커.** `aureole: { c, r }`, `rulerEnds:[[x,y],[x,y]]`, `batonTip`, `eye`. `muzzle`: base·p2는 자의 앞 끝, p3는 `aureole.c`. `face`는 가면 중심이다.

### 3.2 보여야 하는 것

**공통**
1. 위의 `--check`가 모두 ok다(FAIL 0건). 범위: C1을 game·art로 4보스 × 2 = 8건, C2 4건, C4 8건, C7·C8, C10.
2. 판정
   - `hitbox` 점선 원과 feet 점이 bossesB와 같다(C1).
   - 발·밑단이 y 360±3에 닿는다.
   - y 340~360 접지 윤곽이 x 84~300 안에 있다.
   - 몸 높이 280~316(140~158px)이다(납품서에 수치로 적는다).
3. 신호색
   - 산호는 광폭 상태의 바깥 윤곽 펄스뿐이다. 몸 안쪽과 구멍·틈에는 없다.
   - 호박은 준비 자세의 '!'뿐이다.
   - 청록·자수정·연두는 0이다.
4. 1x(C1 `--scale 0.5`)에서:
   - 얼굴 테와 흰 눈빛 점이 따로 보인다.
   - 준비 3벌이 대기와 다른 실루엣이다.
   - P2 표식과 P3 코어가 보인다.
   - 개수 단서를 셀 수 있다: 주교 4, 조수왕 5, 폭군 12, 원장 7−1(`--scale 1`에서 센다).
5. 48px(C3, C3b)
   - 새 4종이 기존 6종과 서로, 그리고 서로끼리 구별된다.
   - 납품서에 보스마다 구별점 한 줄(꼭대기 모양, 덩어리, 소품)을 적는다.
6. 얼굴(C4, C5)
   - 평면 가면은 테와 안 요소의 단축 비율이 같다. 두께 띠는 왼쪽에만 있다.
   - 조수왕 먼 눈은 가로로 눌려 윤곽에 붙는다. 입·눈선은 아래로 휜 호다.
   - 그림자 덩어리 하나 + 액센트 하나이고, 직선 다각형과 두 눈을 지나는 수평 띠가 없다.
   - 얼굴 밖에 가짜 눈(원 + 점, 고리 + 원판)이 0이다.
   - 초상(C5)에서 얼굴이 원 중심 근처에 있고 원의 35~50%를 차지한다.
7. 명도(C6)
   - 회색 변환에서 밝은 순서가 얼굴 > 종이 소품 > 재질 > 몸이다.
   - 몸 덩어리가 지면보다 확실히 어둡다.
   - 큰 종이 면은 얼굴 하나뿐이다.
8. 처치(C8)
   - 4장이 이어진 동작으로 읽힌다.
   - f3은 y 300 위로 솟지 않는다(누운 소품 끝 30 이내 예외).
   - f3에 유물과 종이 ✕ 눈이 있고 산호·호박은 0이다.
9. 범위(C9). 모든 상태의 값 + 16이 x −56~440, y −96~396 안이다.

   - 형식은 `API-bosses2.md`와 같은 절: 불러오는 순서, 박스·피벗 표, 옵션 표, 보스별 상태 표(준비·공격 각 무브, P2 표식, P3 코어, 광폭, 처치), 앵커, 레이어 모델, 토큰, 신호색 소속.
   - 추가로 쓸 것: 보스별 yaw와 얼굴 구성, 상태별 그린 경계 표(C9 결과), 출처(AI 보조 잠정 아트, 바이블 §15).
2. **수치**
   - 보스별 몸 높이(로컬·px)
   - 얼굴 면적 추정(경로 기하로 계산, 몸 대비 %)
   - 재질 패치 면적 추정
   - `META[id].portrait`(center, scale)
   - 앵커 표(대기, 준비 base·p2·p3, 공격 base·p2·p3, 처치 f0~f3)
3. **굽기 여백 제안.** 보스별 `pad`([위, 오른쪽, 아래, 왼쪽], 박스 단위)를 C9 경계로 계산해 적는다.
4. **렌더 목록.** C1~C10 PNG 경로와 `--check` 출력 전문.
5. **지시서와 다르게 한 것과 그 이유.** 좌표는 ±8 로컬까지 자유롭게 바꿔도 된다. 구조 규칙(§1.10)과 §1.2는 바꿀 수 없다.
6. **알려진 한계.** 사람 원화가 필요한 곳을 적는다.

**작업 순서 권장(재작업을 줄인다)**
1. 공용 코어와 조합기를 복사하고 C10이 ok인지 본다.
2. 네 보스의 대기(art·game)와 얼굴을 그린다. 이 단계에서 C3·C4·C5를 먼저 통과시킨다.
3. 준비·공격 3무브를 그린다.
4. 페이즈와 광폭 층을 얹는다.
5. 처치 4장을 그린다.
6. 주교 분신을 그린다.
7. 측정하고 API 문서를 쓴다.

**멈출 조건.** 지시서가 바이블과 부딪치면 그 자리에서 멈추고 납품서에 적는다(kit-artist 규칙).

## 6. 메인 세션 참고 (등록·굽기, 합격 뒤)

1. **킷 로드 목록.** `scripts/build-atlas.mjs`와 `scripts/build-ui-art.mjs:17`의 `KIT_FILES`에 `k-bosses3.js`를 `k-bosses2.js` 뒤에 넣는다. 리뷰 스크립트는 이미 자동으로 읽는다.
2. **굽기 사양**(`art/atlas-spec.mjs:77-101`)
   - `BOSS_MODULES.bossesC = { box: [384, 384], anchor: [192, 360], scale: 0.5, options: { detail: 'game', shadow: false } }`
   - `BOSS_SPRITES`에 다음 네 항목을 넣는다. pad는 납품서 값을 쓴다.
     - `'boss/2/bishop': { kit:'bishop', module:'bossesC', bossId:'s2-mid-clones', chapter:2, pad }`
     - `'boss/3/tide-king'`, `'boss/4/tyrant'`, `'boss/5/director'`도 같은 방식이다.
   - `bossStates()`에 `phaseN-attack[-enraged]`와 `death`(frames 0~3)를 더한다.
   - **SYS-05가 무브를 만들기 전에는 phase 2·3을 `move:'base'`로 굽는다.**
3. **슬롯과 초상**
   - `src/game/render/assets/slots.ts:33-40`의 `BOSS_SLOTS`에 등록한다.
   - `art/ui-art-spec.mjs:35-42`의 `BOSS_PORTRAITS`에 `module:'bossesC'`와 납품서의 center·scale을 넣는다.
   - `build-ui-art.mjs:125-135`의 `bossPortrait` 레시피와 `art-review-sheet.mjs:84-88`의 `bossCall`에 bossesC 분기를 더한다(지금은 bossesA·bossesB만 있다).
4. **렌더러.** attack·death 상태를 고르는 코드를 넣는다. 분신 미끼는 P3 문법이 생길 때 쓴다.
5. **확인.** `npm run build:atlas`, `npm run build:ui-art`, `npm run test:unit`, `npm run build`(설치 에셋 예산), `npm run test:visual`.
   - 볼 장면: 2-5·3-5·4-5·5-5 보스전(평상·광폭·준비), 보스 배너 초상.
   - 커밋 항목은 ART-07·ART-08(D-14)이다.
