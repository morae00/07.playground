## 1. 범위

- **만드는 것**: 7명 각각의 인게임 스프라이트(idle 6 · run 8 · throw 4 · hurt 3)와 HUD·메뉴 카드용 원형 초상 6표정(calm · focus · hurt · lowhp · awakened · victory).
- **상태 목록 정정**
  - 발주문은 상태를 "idle·move·hurt·throw·death 등"으로 적었다.
  - 그러나 결의 킷과 굽기에는 idle·run·throw·hurt 4상태만 있다(`art/atlas-spec.mjs:24-29`, `API-hero.md` §6 "death … 미구현").
  - 렌더러는 death를 hurt로 대신한다(`src/game/render/animation.ts:58`). cast·skillBurst는 throw로 대신한다(`:53-54`).
  - 그래서 이번 발주는 결과 같은 4상태다. death는 결까지 8명을 한 번에 따로 발주할지 팀이 정한다(§12 Q1).
- **6표정이 모두 필요한 이유**
  - HUD가 hurt → lowhp → focus → awakened → calm 순으로 표정을 고른다(`docs/ARCHITECTURE.md:146-151`).
  - 정산 화면이 victory와 hurt를 쓴다(`:178`).
- **하지 않는 것**
  - 전신 일러스트, 키아트, 정산 포즈, 하·상 방향 프레임, rooted·silenced 오버레이(렌더러 몫), death
  - 등록·굽기·렌더러 코드(메인 세션 몫)
  - `k-hero.js`를 포함한 다른 모듈의 수정

## 2. 모듈과 API (기존 모듈과 같은 문법, `art/concept-kit/README.md`, `docs/art/handoff-r4.md` §1)

```
PN.characters.ids        // ['dan','noeul','seori','dok','hwi','ryeong','wol'] (characters.ts 순서, 결 제외)
PN.characters.all        // ['gyeol', ...ids]
PN.characters.SPRITE     // PN.heroKit.SPRITE와 같은 값: {w:96,h:96,pivot:[48,60],r:15,height:64,top:-49,feet:15,
                         //   shadow:{cy:8.25,rx:15,ry:6.5}, ring:{cy:8.25,rx:24,ry:10.3},
                         //   frames:{idle:6,run:8,throw:4,hurt:3}, fps:{idle:8,run:14,throw:16,hurt:12}}
PN.characters.PORTRAIT   // {w:160,h:160,pivot:[80,80],r:74,exprs:['calm','focus','hurt','lowhp','awakened','victory']}
PN.characters.META[id]   // {weapon, eye:[x,y], headTop, extent:[x0,y0,x1,y1], muzzle:[x,y], cyan:'<부위>',
                         //  face:'lit'|'shade', portrait:{headScale, dx, dy, faceBox:[x,y,w,h]}}
PN.characters.sprite(id, state, frame, opts)   → 96×96 박스 SVG 문자열
PN.characters.portrait(id, expr, opts)          → 160×160 박스 SVG 문자열
PN.characters.sheet(id, opts)                   → 검토용: 4상태 전 프레임, 96칸 격자(행 = 상태)
PN.characters.portraitSheet(id, opts)           → 검토용: 6표정 한 줄(160칸)
PN.characters.lineup(opts)                      → 검토용: 결 + 7명 한 줄(96칸 × 8 = 768×96)
PN.characters.portraitLineup(expr, opts)        → 검토용: 결 + 7명 초상 한 줄(160칸 × 8)
PN.characters.placeSprite / placePortrait       → heroKit과 같은 피벗 기준 배치
PN.characters.version = '1.0'
```

- **sprite 옵션**: `ring`(true), `aim`(0), `flip`(false), `shadow`(true), `halo`(true), `xray`(false), `xrayOnly`(false), `noOutline`(false)는 `PN.heroKit.sprite`와 같은 뜻이다(`k-hero.js:1535-1558`). 추가 옵션은 `mono`(false)다.
  - mono는 모든 채움과 선을 먹 하나로 바꾸고 白邊을 끈다.
  - 외곽선 필터는 유지한다. 그래야 구운 실루엣과 같은 모양이 된다.
- **portrait 옵션**: `frame`(true), `bg`(true)는 heroKit과 같다. `mono`는 선택이다.
- **lineup 옵션**: `{ mono, state:'idle', frame:0, ground: '#hex'|null, enemies: 장 번호|null }`. `enemies`를 주면 그 장의 stalker와 warden을 game LOD로 오른쪽에 붙인다. 명도 대조용이고, `PN.enemies`가 없으면 생략한다.
- **'gyeol' 위임**
  - `sprite('gyeol', …)`는 `PN.heroKit.sprite(state, frame, opts)`를 그대로 돌려준다. mono일 때만 이 모듈이 색을 바꾼다.
  - `portrait('gyeol', …)`는 `PN.heroKit.portrait`다.
  - 모르는 id·state·expr를 받으면 `throw new Error`. 굽기가 조용히 다른 그림을 굽지 않게 한다.
- **로드 순서**
  - `lib.js` → `k-hero.js` → `k-characters.js`.
  - `PN._hk`는 **호출 시점에만** 읽는다. 로드 시점에 읽으면 안 된다.
  - 리뷰 시트는 새 모듈을 k-hero 뒤에 읽는다(`scripts/art-review-sheet.mjs:30-31`). 굽기 스크립트에는 메인 세션이 넣는다(§10).
- **PN._hk에서 써도 되는 것** (범용 도구)
  - `K`, `f`, `pt`, `T`, `Ctx`, `V`, `smooth`, `poly`, `limb`, `limbShade`, `shadowEdge`, `litEdge`, `inkHem`, `hemLine`, `splat`, `negate`, `spriteRing`, `brushArc`
- **PN._hk에서 쓰면 안 되는 것** (결의 생김새)
  - `head34`, `hat34`, `neck34`, `FACE`, `sHead`, `sCoat`, `sRibbon`, `sArm`, `sBody`, `scarf*`, `bandolier`, `spool`, `hand`(검은 장갑)
  - `PN._hk`에 무엇도 더하거나 고치지 않는다. 결의 FACE 점열(`k-hero.js:176-178`)과 `edge()` 방식(`:199-222`)은 **복사**해서 쓴다.
- **id**
  - 호출마다 고유해야 한다. `PN._hk.Ctx`를 쓰면 `hk<N>_` 카운터를 공유하므로 자동으로 고유하다.
  - 직접 만들면 `kc<N>_` 접두사를 쓴다.

## 4. 7명 공통 디자인 규칙

### 4.1 소속(P1·V2)과 면적
- **종이 몸이 아군이다.** 밝은 면은 `#F3EEE2`·`#FAF6EC`·`#D8D0C0`(Y ≥ 0.69)만 쓴다. 어두운 면은 `#121110`·`#2B2926`(Y ≤ 0.06)만 쓴다. 중간 회색은 없다(바이블 §4.2).
- **면적**: idle f0, `noOutline` 채움 기준이다(`API-hero.md` §2의 측정법).
  - 종이 ≥ 50%(모자 포함), 먹 ≤ 40%, 청록 5~10%.
  - hurt 반전 프레임을 뺀 모든 프레임에서 청록 ≥ 3%.
- **청록 서명은 인물마다 '청록 천 하나'다.** 결의 목도리처럼 몸에서 유일한 청록 면이다(바이블 §9). 무기에 청록을 조금 더해도 되지만 합계가 위 범위 안이어야 한다.
  - 모든 청록 면은 샌드위치로 그린다: 먹 외곽 + `#00A8C6` + `#007C94` 밑면 + `#CFF6FF`나 종이 심 한 줄(바이블 §5.3).
  - 청록만으로 된 선은 금지다. 실·번개는 먹·청록·glow 세 겹 획이다(결의 바늘 실 꼬리 `k-hero.js:142-143`과 같다).
- **먹이 위로 스민다.** 소매 끝, 옷단, 동정 끝에 먹 스민 끝단을 넣는다. 64 px에서는 1~1.5 px 띠다(바이블 §6-7, 결의 코트 옷단 `k-hero.js:1419`).
- 블랙 스팟은 디자인한 덩어리로 넣는다: 머리카락, 모자, 허리띠, 신, 소품. 먹 면적 상한 안에서 인물마다 배치가 다르다(§6).

### 4.2 금지 (어기면 반려)
| 무엇 | 왜 |
|---|---|
| 먹 덩어리(머리카락·모자·단지 뚜껑) 안에 **떠 있는** 흰 점·원·초승 | 먹귀의 '종이 구멍 눈' 문법이다(바이블 §10.1). R4에서 흰 점은 눈빛 하나로 정했다. 비녀·동곳·머리끈처럼 덩어리 위의 종이 표시는 그 덩어리를 **가로질러 밖으로 나오는** 띠나 획이어야 한다 |

## 5. 얼굴: R4 처방의 적용 (최우선)

### 5.1 공통 구조 (초상, 머리 좌표)
- **좌표계는 결과 같다**: 원점은 두개골 중심, 오른쪽을 본다, 턱 끝 y ≈ +32.5(`k-hero.js:164-170`).
- 모든 머리는 결과 **같은 약 45° 3/4 한 시점**이다. HUD에서 8명이 같은 각도로 보여야 한다.
- 결의 FACE 점열 24점(`k-hero.js:176-178`)을 복사한 뒤, 인물별 덮어쓰기(§6)만 바꾼다. 점 번호는 0부터 센다.
  - 5·6 먼 눈썹뼈, 7 먼 눈확 오목, 8 먼 광대, 9·10 코끝, 11 코밑, 12 콧방울-뺨
  - 13 윗입술, 14 먼 입꼬리, 15 아랫입술, 16 턱 홈, 17·18 턱 앞, 19 턱 밑, 20 턱밑선, 21 가까운 턱각, 22·23 가까운 옆면
- **바꾸면 안 되는 것** (어기면 입체파가 다시 생긴다)
  - 가로선: 눈썹 −8, 눈 −3.5(±0.6), 코밑 10, 입 17.5(±1), 턱 32.5(±2.5).
  - 정중선은 눈높이에서 x 20 ± 1이다. 콧등은 두 눈 안쪽 끝 사이(x 19~21)에서 시작한다.
  - 가까운 눈은 x 2.4~13.4, 먼 눈은 x 21.8~28.0이다. 먼 눈 폭은 가까운 눈의 0.55~0.6이고, 콧등 너머·먼 윤곽 안쪽에 있으며 바깥 끝이 윤곽 획에서 1u 이상 떨어진다.
  - 먼 윤곽은 관자 → 눈썹뼈 → 눈확 오목(깊이 1.5~2.6u) → 광대 → 코끝 순서다. **코끝만** 광대선 밖으로 1.3~3u 나온다.
  - 이마-콧등-입술이 한 줄로 이어지는 옆얼굴 구간은 없다. 먼 입꼬리는 먼 윤곽 위에 있다.
- **바꿔도 되는 것**: 턱각·턱밑·턱 앞(±3u), 광대(±1u), 코끝 크기·높이(±1u), 입 높이(±1u), 눈 모양(아래 범위 안), 눈썹, 입술, 나이 표시.
- **윤곽 획**
  - 결의 `edge()`처럼 FACE 점열을 그대로 따르는 붓 획 3개로 긋는다(`k-hero.js:199-222`).
    - 이마~광대~코끝 2.6~3.0u(먼 눈확에서 0.7배로 가늘게)
    - 코밑~턱 앞 2.2 → 4.2u
    - 턱 끝 4.2~5.2u
  - **턱밑에서 목까지는 획이 없다.** 목 그림자 띠가 경계다(`k-hero.js:319-324`).
  - 이목구비 선은 끝을 가늘게 뺀다.
  - `bold`(초상 1.25)는 선 굵기 배수일 뿐이다. 위치와 크기를 키우지 않는다(R4 H1).
  - AD 스케치처럼 점 3개짜리 획으로 윤곽을 대신 그리면 턱에 검은 초승달이 생긴다(`faces-portrait2.png`에서 확인). 반드시 점열을 따른다.

### 5.2 명도: 얼굴 안은 3단(종이 · `#D8D0C0` 평면 · 먹)
- **A형 '그림자 얼굴'** (결, 령)
  - 그림자 덩어리 하나가 형태를 감는다: 먼 눈썹 → 콧등 뿌리 → 가까운 눈 아래 → 광대 → 옆면 → 턱각. 경계는 날카롭고 직선 구간은 8u 이하다.
  - 가까운 눈은 그림자 속에서 아래 눈꺼풀 종이 획과 눈빛 한 점으로만 보인다.
  - 악센트는 코 그림자 하나다(R4 H1).
- **B형 '빛 받는 얼굴'** (단, 노을, 서리, 독, 휘, 월)
  - 얼굴 안에 먹 그림자 덩어리를 두지 않는다. 블랙 스팟은 머리카락·모자와 목 그림자 띠(턱선 바로 아래)가 맡는다.
  - 얼굴 안에는 종이 그늘 평면 3개와 먹 악센트 하나(코끝 아래 쐐기)를 둔다.
    - 먼 뺨 띠: 결의 `FAR_TONE`(`k-hero.js:193`)
    - 코 옆면: 결의 `NOSE_TONE`(`:196`)
    - **가까운 옆면**: 곡선 경계 (−3.4,−14) → (−1.2,−5) → (0.4,2.6)[광대에서 부풂] → (−1.6,9) → (−6.6,16)[턱각]. 이 경계와 머리카락·귀 사이를 채운다. FACE로 자른다.
    - AD 검증 경로: `M -3.4,-14 C -2.2,-10 -1.4,-7 -1.2,-5 C -0.6,-1.6 0.6,0.6 0.4,2.6 C 0.2,5.4 -0.6,7.4 -1.6,9 C -3,11.6 -4.8,14 -6.6,16 L -16,16 L -16,-14 Z`
  - 곧은 수직 띠나 얼굴을 가로지르는 수평 띠는 금지다(`faces-portrait2.png` 휘에서 확인한 실패).
  - 인물별 추가 평면(아랫입술, 수염 자리, 볼 그늘)은 §6에 있다. 한 얼굴에 평면은 6개를 넘기지 않는다.
- 두 눈을 가로지르는 수평 그림자 띠는 금지다(바이블 §9, v1.0 §8.1).

### 5.4 64 px 스프라이트 얼굴 (R4 H5 적용)
- **B형**
  - 먹 눈 표식 하나: 1.2~1.6 × 1.4~1.8 px, `META.eye` 중심.
  - 눈썹 쪽을 뺀 사방에 1 px 이상 종이 여백.
  - 눈썹을 그리면 눈과 1 px 이상 띄운다.
- **A형(령)**
  - 종이 눈빛 2×2 하나, 사방에 1 px 이상 먹 여백(결 `k-hero.js:1433-1434`와 같다).

### 5.5 초상 공통 (규격·표정·배경)
- **규격**은 결과 같다(`k-hero.js:1568`, `:1612-1615`): 160 박스, 원 r 74로 자름, 먹 테 6, 종이 링 r 78.5. 그림은 r 79 밖으로 나가지 않는다(굽기 칸 검사). 망점 피치는 6 이상이고 얼굴·목에는 망점이 없다.
- **구도**
  - 머리 원점은 `hx = 64.08 + dx`, `hy = 72 + dy`이고 배율은 `headScale`이다(결은 1.72, 0, 0. `k-hero.js:1599`). 인물별 값은 §6.
  - 합격 범위
    - calm의 가까운 눈 중심이 원 중심에서 가로 ±8, 세로 ±14 안에 있다.
    - 코끝이 테 안쪽 12 이상이다.
    - 턱 끝이 원 안에 있다.
    - **모자·머리 서명이 원 안에 보인다.**
    - 얼굴 높이(눈썹선~턱)가 60~72 단위다(배율 1.48~1.78).
- **옷깃**: 원 아래에 인물의 옷깃과 **청록 서명의 일부**가 보인다. 결의 목도리 매듭과 같은 역할이다.

  - lowhp: 20% 망점 + `#B8352B` 점선 테
  - awakened: 청록 호 3줄 + 청록 점선 테
  - victory: 종이 반짝이

### 5.6 R4에서 고친 실수: 이번에도 금지
1. 옆얼굴 윤곽 위에 3/4 눈을 얹는다. 두 눈이 콧등의 같은 쪽에 있다.
2. 그림자가 형태와 상관없는 직선 다각형이다.
3. 얼굴 안이 종이와 먹 2단뿐이다.
4. 균일한 윤곽선이 턱밑과 목까지 얼굴을 닫는다.
5. 눈빛 말고 흰 점이 또 있다(보조 점, 그림자 속 땀).
6. bold가 위치를 키운다.
7. 망점 피치가 3 px 미만이다(84 px 기준).
8. 블러 발광이 있다.
9. 손이 코 앞을 가린다.
10. focus 입에 꼬리가 있다.
11. 스프라이트에 먼 눈 점이 있다.

## 6. 인물별 지시

좌표는 스프라이트 로컬(원점 = 피벗, y −49 = 결의 흑립 꼭대기, y +15 = 발)이다. 초상 값은 머리 좌표다. 모두 AD 러프·스케치에서 렌더로 확인한 출발점이다. ±1.5 단위 안에서 다듬어도 되지만, 실루엣 열쇠와 §5.1의 불변값은 지킨다.

### 6.1 단 (dan) · 칼잡이 · 부채 단검 `fanKnives` · 공격속도
- **인물(제안)**: 20세 전후 남. "부채 단검을 쉬지 않고 던지는 날랜 손"(`ko.json:865`). 손이 말보다 먼저 나간다. 늘 반쯤 웅크린 준비 자세로, 무게는 발끝에 둔다.
- **실루엣 열쇠**
  1. **몸 앞으로 편 칼 부채.**
     - 사북(손)은 (12,−13)이고, 반지름 14로 −100°에서 −5°까지 편다.
     - 바깥 가장자리는 **칼끝 7개 톱니**다. 칼끝은 r 14, 사이의 홈은 r 11.6이다.
     - 종이 면에 먹 부채살을 긋는다. 매끈한 호는 반원 방패로 읽혀 금지다.
  2. 작은 머리. 상투 꼭대기 y −41.5. 뒤통수 매듭에서 짧게 갈라진 띠 꼬리 2개(끝 (−14.5,−39)·(−15,−29.6)).
  3. 엉덩이 길이의 짧은 저고리. 굽힌 다리(무릎 (9,5)·(−7,6))로 다리 사이가 뚫린 낮은 자세.
- **복식·명도**
  - 종이 저고리. 등 쪽 절반은 먹 배자(조끼), 먹 허리띠.
  - 허리에 접은 부채 3자루(먹 막대, 가슴에 비스듬히 꽂지 않는다. 결의 탄띠와 겹친다).
  - 종이 바지에 먹 대님(발목 끈, 달리기 리듬 표식), 먹 신. 맨손.
- **청록 서명**: 이마를 두른 머리띠(높이 2 px)와 뒤통수 매듭에서 갈라진 뾰족한 꼬리 2개(각 ≤ 10 px). 부위는 **머리**다.
- **동작**
  - idle: 손목을 까딱여 부채를 70° → 95° → 70°로 폈다 접는다. 띠 꼬리가 펄럭인다.
  - run: 기울기 16°. 부채는 45° 이상 편 채로(반지름 ≥ 10) 몸 앞 아래에 든다. 다 접힌 막대 상태로 뛰지 않는다. 가장 자주 보이는 상태에서 열쇠 ①이 사라지기 때문이다.
  - throw(앞 부채꼴 단검): draw 부채를 접어 가슴 앞으로 → wind 팔을 뒤로 젖힌다 → snap 팔을 휘두르며 부채가 확 펴지고, 종이 단검 3자루(종이백, 먹 칼끝, 먹 외곽)가 ±15° 부채꼴로 앞으로 날아간다 → follow 부채를 150°로 활짝 펴고 단검 잔획을 남긴다.
  - hurt: 공통 + 부채가 반쯤 접힌다.

### 7.3 시험 명령과 합격선
kit-artist도 실행할 수 있는 명령이다. 결과는 메인 세션이 아니라 저장소 밖 임시 폴더에 생긴다.

1. **단색 실루엣 줄(실제 크기·최소 배율·확대)**

   - **합격**
     - 7.1 표대로 8명이 서로 다르다. 머리만 자른 줄에서도 8개가 모두 다르다.
     - run 줄에서도 열쇠 ①이 보인다(단의 부채가 펼쳐져 있다).
2. **색 줄과 명도(P1)**

   - 같은 식으로 5장(`"#ABA5AC"`, `enemies: 5`)을 1배와 3배로 렌더한다.
   - **합격**
     - 8명 모두 바닥과 적보다 밝다.

## 11. 킷으로 고칠 수 없는 것 (사람 원화, 바이블 §15)
1. **인물별 머리 모델 시트**: 정면·3/4·옆·뒤 턴어라운드와 6표정. 7명 모두 필요하다. 눈꺼풀 두께, 입술 볼륨, 머리카락 결, 실제 붓 비백은 절차형 테이퍼로 낼 수 없다(R4 §5와 같다).
2. **64 px 얼굴과 소품의 픽셀 클린업.** 줌 리샘플(0.8×·1.0×·1.2×)마다 눈 표식, 부채살, 활 시위, 방울의 픽셀이 달라진다.
3. **의상 주름과 소품 재질의 최종본**: 백자 유약, 각궁 결, 정자관 말총, 한삼 비침.
4. **판독 시험**(바이블 §14, 사람 참가자 n ≥ 8): 결 + 7명 0.3초 구별.
