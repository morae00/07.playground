## 0. 한눈에

- 다섯 보스는 "지움의 다섯 직분"이다(로어 §3.2). 공백을 섬기는 자는 얼굴이 지워졌으므로(로어 §3.1), 다섯 모두 **얼굴 자리에 판**을 단다: 가면, 문자판, 렌즈, 유리창, 종이. 그 판이 약점이고 레티클 자리이며 초상의 중심이다.
- 판 위의 눈은 장 지문을 따른다: 1장 슬릿, 2장 열쇠 구멍, 3장 겹원 기포, 4장 문자판, 5장 일식 고리.
- 박스와 피벗은 bossesB와 같다(384, (192, 252)). 판정은 r76 로컬(게임 r38)이고 **발 y는 328**이다. 게임에서는 0.5배로, 키 100~110px이다.
- 경량 세트로 보스마다 7장을 그린다: 대기, 준비, 공격, 처치 0~3. 광폭화 그림은 그리지 않는다. 페이즈 균열은 선택이다.
- 얼굴은 한 시점(오른쪽 30°, 위에서 10°)에서 **좌표를 계산해** 그린다(§2). 지금 킷 얼굴이 입체파처럼 보이는 원인 다섯 가지를 피한다.

## 1. 모듈 공통 계약

### 1.1 파일과 의존성

- `art/concept-kit/k-bosses4.js` 하나에 `window.PN.fieldBosses`를 만든다.
  - `lib.js`(`PN.taper`, `PN.rng`, `PN.halftone`)에만 의존한다.
  - `PN.bossesB._`의 도우미는 호출하지 말고 이 파일에 **복사**한다. 굽기 쪽 로드 순서가 바뀌어도 깨지지 않게 하려는 것이다.
  - 다른 모듈과 원본(`lib.js` 등)은 고치지 않는다.
- id는 호출마다 접두사 `kb4_<n>_`(모듈 카운터)를 붙인다. 루트는 `<g class="kb4 kb4-<id>">`이고 그 안에 자기 `<defs>`를 둔다.
- 구조는 bossesB 합성기를 따른다(`k-bosses2.js:845–937`).
  - 보스마다 `parts[id](X, o)`가 층 `under · back · fig · holes · rims · over · solid · front`를 돌려준다.
  - 합성기가 다음을 처리한다: 그림자 쪽 굵기(먹 복제를 오른쪽 아래로 민다), 녹아웃 헤일로(feMorphology), 단색(mono), 판정 겹침(hitbox).
  - **얼굴판만은 따로 그린다.** art의 거친 먹선 필터(rough) 그룹 밖에 `face` 층을 두고 fig 위에 그린다. 그래야 이목구비와 눈금이 흔들리지 않는다. 얼굴판은 몸 윤곽 안에 있으므로 헤일로와 실루엣에는 영향이 없다.
- 그림 안에 글자를 한 자도 넣지 않는다. 계급장, 도면 치수, 문자판 숫자, 판결문 모두 무늬와 눈금으로만 그린다. 글자처럼 읽히는 기호도 금지다.

### 1.5 `PN.fieldBosses.anchors(id, opts)`와 메타

- 공통 키: `pivot`, `feet`, `r`, `shadow`.
- 보스와 pose에 따라 바뀌는 키:
  - `head`: '!'와 상태 아이콘이 놓일 자리의 아래 중앙. 모자·두건·등짐 꼭대기에서 6 이상 위.
  - `face`: 밝은 얼굴판의 눈빛 근처. 레티클과 피격 섬광 자리다.
  - `faceBox`: 밝은 얼굴판을 감싸는 상자 `[x, y, w, h]`. 면적 검사와 검수 크롭에 쓴다.
  - `muzzle`: 공격이 나오는 소품의 점.
  - 보스별 추가 키(§3).
  - death pose에서는 face·head를 대기 값 그대로 돌려줘도 된다.
- `portrait: { center: [x, y], scale }`: 대기 자세 기준이고 `BOSS_PORTRAITS`에 그대로 들어간다.
  - 원 지름은 scale × 384 로컬이다.
  - 밝은 얼굴판과 그 테가 원 지름의 35~55%를 차지하게 한다.
  - 눈높이는 원 위에서 40~50% 자리에 온다.
  - 높은 모자나 두건 꼭대기는 잘려도 된다(결의 초상처럼). 다만 모자 모양은 알아볼 수 있어야 한다.
- 메타:
  - `PN.fieldBosses.META[id] = { name, bossId, chapter, pattern, env: {light, base, deep, spot}, box, pivot, feet, r, gameScale }`
  - `PN.fieldBosses.ids`, `PN.fieldBosses.BOX`, `PN.fieldBosses.K`

### 1.6 선·명도·색·질감

**선**
- game에서 바깥 외곽선이 보이는 폭은 7(3.5px@1x, §3 필드 보스)이다.
- 그림자 쪽(오른쪽 아래) +40%는 합성기의 먹 복제로 만든다.
- 내부선은 3(1.5px)이다. art는 bossesB art와 같은 계수를 쓴다.
- 긴 윤곽은 2~4획으로 끊는다. 빛 쪽 틈은 art에서만 1~2곳 둔다. **발밑과 하단 윤곽은 끊지 않는다.**

**명도(§4.2)**
- 몸의 70% 이상은 ink, ink700, ink500이다.
- 왼쪽 위에 ink500 명부를 쐐기나 초승달 2~3개로 얹고, 경계는 지그재그로 한다.
- 오른쪽 아래는 ink 덩어리 하나로 비운다.
- art에서는 왼쪽 위 윤곽에 ink300 비백 림 1px을 준다.

**재질색**
- 장 재질색은 `env.chN.deep` 하나만, 몸의 20% 이하로 쓴다: 1장 #8F836C, 2장 #878A93, 3장 #8A9288, 4장 #978A70, 5장 #8A848C.
- spot색과 `CHAPTER_ART` accent는 쓰지 않는다. §5.2에서 spot은 캐릭터에 금지이고, 2·5장 accent는 채도 한도를 넘는다.

**밝은 면**
- 밝은 얼굴판은 하나다. 보스 면적의 12% 이하로 하고, 굵은 먹테로 액자처럼 두른다(game 6 이상, art 3 이상).
- 그 밖의 종이 조각(깃, 벽보 띠 등)은 합계 10% 이하이고 먹테 6(game)을 두른다.
- 얼굴 말고 두 번째로 큰 밝은 면을 만들지 않는다.

**망점과 해칭**
- 망점은 20/40/60%, 45°, game 피치 6 이상(3px@1x), art 피치 4.4. 한 부품에 2단계까지만 쓴다.
- 펄럭이는 천(망토 자락, 두건 꼬리, 법복 자락)에는 망점을 쓰지 않는다.
- 사선 해칭(평행선 묶음)은 몸 어디에도 쓰지 않는다(§6-5). 금, 주름, 도면 선은 갈라지고 휘는 선으로 그린다.

**드립**: 옷단과 몸 끝에서 먹 방울 2~3개가 아래로 흐른다(§6-7).

**신호색**
- 호박은 windup의 '!'에만 쓴다. bossesB `exclaim`(`k-bosses2.js:118–127`)과 같은 크기·샌드위치(먹 + 호박 + 종이 심, game ×1.25)다.
- 몸 그림에 산호·청록·자수정·연두는 0이다. 발광과 가산 합성도 0이다.

**토큰**
- bossesB `K`와 같은 hex를 쓴다: ink #0E0E10, ink700 #2B2926, ink500 #46423D, ink300 #8C8579, paper50 #FAF6EC, paper #F3EEE2, paper300 #D8D0C0, voidPaper #E2DBCB, warn #D88D16.
- 굽기의 `COLOR_MAP`(`art/atlas-spec.mjs:14–21`)이 이 값을 구현값으로 바꾼다.
- 1·2장 장색은 `k-bosses1.js:15–16`의 값을 쓴다.

**장마다 윤곽 성질**(v1.0 §9.3을 보스에도 적용)
- 1장: 거친 번짐
- 2장: 철선묘(고른 쇠줄 선)
- 3장: 아래로 흐르는 젖은 번짐
- 4장: 딱딱하게 꺾인 기계선
- 5장: 가장자리가 지워진 흑요(투명하게 물린 자리)

**game 디테일**은 축소본이 아니라 다시 그린 그림이다(§3). 남길 것은 키우고 미세 디테일은 뺀다(§2.5, 보스별 지시).

## 2. 얼굴: 공통 설계 (최우선)

### 2.1 지금 킷의 실수 (따라 하지 않는다)

1. **한 얼굴에 두 시점이 있다.**
   - 결의 3/4 얼굴은 오른쪽 윤곽이 거의 옆얼굴 프로필이다: 코끝이 이마선 밖으로 5 나오고 입술·턱 계단이 있다(`k-hero.js:169` FACE).
   - 그런데 두 눈은 약 25° 각도의 간격으로 그 안쪽에 나란히 있다(`:192` 가까운 눈 x 9.6, `:206–207` 먼 눈 x 26.6).
   - 윤곽과 눈이 서로 다른 각도라 입체파처럼 읽힌다.
2. **판과 그 위 요소가 다른 평면에 있다.**
   - 톱니 전령의 나팔 종구는 축 방향으로 0.69 눌린 타원이다(`k-bosses2.js:455`, 27 × 39).
   - 그런데 문자판은 `scale(0.84,1) rotate(−ang)`로 화면에 똑바로 다시 세웠다(`:457`). 판은 돌아갔는데 눈금과 바늘은 정면이다.
   - 걸쇠 여제의 로켓도 테는 기울었는데 두 눈은 정원이다(렌더 `boss-faces` s3, 확인).
3. **형태와 상관없는 직선 다각형 그림자.** 결의 흑립 그림자는 직선으로 꺾인 다각형이다(`k-hero.js:171` SHADOW). 얼굴 곡면을 따르지 않고 얼굴을 자른다.
4. **정면 판을 3/4 몸에 붙였다.** 잉크 도살자의 종이봉투는 3/4 몸 위에 정면 직사각형으로 붙어 있다(렌더 `boss-faces` s1-mid-dash, 확인).
5. **글자처럼 읽히는 기호.** 도살자 식칼의 game 글리프가 'HOI'처럼 읽힌다(렌더 `bosses` s1-mid-dash-p1, 확인).

### 2.2 시점은 하나다

- 다섯 보스 모두 머리와 얼굴판을 **오른쪽으로 30° 돌리고(yaw), 위에서 약 10° 내려다본** 한 시점으로 그린다. 몸의 방향과 같다.
- 포즈에 따라 머리를 숙이거나 기울일 수 있다(pitch·roll ±15°). 그래도 yaw는 그대로이고, 판 위의 모든 요소를 같은 변환으로 다시 계산한다.
- 한 얼굴에 정면 요소와 옆면 요소를 섞지 않는다.
  - 정면 요소: 정원인 판, 좌우 대칭인 두 눈, 정면 입.
  - 옆면 요소: 코·입술·턱 계단이 있는 프로필 윤곽.
- 30°에서 먼 쪽 윤곽에 보이는 것은 광대에서 한 번 들어가는 굴곡과 코끝(윤곽 밖 2 이하)뿐이다.

### 2.3 좌표를 계산해서 그린다

SVG transform으로 판을 늘이면 선 굵기가 방향마다 달라진다. 그러니 점을 아래 함수로 바꿔 경로를 만든다. 그러면 선 굵기는 그대로 남는다.

```js
// 평평한 판(문자판, 렌즈, 유리창, 유리창 속 얼굴). 정면 설계 좌표 (u, v), 반지름 50 기준.
// c = 판 중심(로컬), R = 실제 반지름, tilt = 판 전체 기울기(°, 시계 방향 +), squash = 위에서 본 세로 눌림
function plane(c, R, { yaw = 30, tilt = 0, squash = 0.97 } = {}) {
  const k = R / 50, sx = Math.cos(yaw * Math.PI / 180), a = tilt * Math.PI / 180;
  return (u, v) => {
    const x = u * k * sx, y = v * k * squash;
    return [c[0] + x * Math.cos(a) - y * Math.sin(a), c[1] + x * Math.sin(a) + y * Math.cos(a)];
  };
}
// 판의 두께: 테를 왼쪽으로 t·sin(yaw)만큼 민 두 번째 테와 원래 테 사이의 초승달.
// 오른쪽으로 돌린 판은 왼쪽 두께만 보인다.

// 머리를 감싸는 가면(장교의 회벽 가면, 심판관의 종이 가면): 세로 원통에 감는다.
// phi = 얼굴 중심선에서 돈 각(°, 먼 쪽 +), h = 위아래 위치(로컬, 아래 +), rho = 머리 반폭
function wrap(c, rho, { yaw = 30, look = 0.07 } = {}) {
  return (phi, h) => {
    const a = (phi + yaw) * Math.PI / 180;
    // k = 그 자리의 가로 단축. 요소 폭에 곱한다. k ≤ 0이면 안 보인다.
    return { p: [c[0] + rho * Math.sin(a), c[1] + h + look * rho * Math.cos(a)], k: Math.cos(a) };
  };
}
```

`wrap`에서 나오는 위치(yaw 30°, 머리 보이는 폭의 왼쪽 끝 = 0%):

| 요소 | phi | 위치 | 폭 |
|---|---|---|---|
| 중심선 | 0° | 75% | — |
| 가까운 눈 | −28° | 52% | × 1.0 |
| 먼 눈 | +28° | 92% | × 0.53(가까운 눈의 약 절반) |
| 입꼬리 | ±22° | — | — |
| 귀(보이면) | −95° | 왼쪽 5~10% | — |

- 눈선, 입선, 모자 띠 같은 가로선은 아래로 볼록한 호가 된다.
- 판 위 요소의 폭과 간격도 같은 함수에서 나온다. 먼 쪽의 실 땀, 눈금, 금은 더 촘촘하고 좁아진다.

### 2.4 그림자, 명도 전이, 선 위계

**그림자.** 키 라이트는 왼쪽 위다. 얼굴판마다 **그림자 덩어리 하나와 액센트 하나**만 둔다.
- 평평한 판:
  - 덩어리는 두건이나 챙이 판 위쪽에 드리운 초승달 하나다. 그 아래 경계는 판과 같은 `plane` 호다.
  - 액센트는 테 안쪽 오른쪽 아래의 먹 두께선이다.
- 감은 가면:
  - 덩어리는 먼 쪽 볼 면(phi +35°보다 바깥)을 관자놀이에서 턱까지 감는 세로 띠 하나다.
  - 액센트는 코 밑 쐐기다.
- 그림자 경계는 형태를 따르는 곡선이다. 직선 다각형과, 두 눈을 가로지르는 수평 띠는 금지다(§9).

**명도 전이.** 밝은 면(paper 또는 paper50) → 반그늘(paper300 평면. art는 20% 망점 가능) → 그림자(ink300 평면 또는 40% 망점) → 먹테 순서로 잇는다. game은 망점 없이 평면 3단(paper, paper300, ink)이다.

**선 위계(game, 로컬 단위)**
- 몸 외곽 7 > 얼굴판 테 6 > 이목구비(눈테, 눈썹, 입선) 3~4 > 금, 눈금, 실 땀 2.
- 이목구비는 `PN.taper`로 끝이 가늘어지는 붓선이다.
- 얼굴 안에서 같은 굵기 선을 세 개 넘게 쓰지 않는다.

**눈빛.** 밝은 점에는 주변 먹 여백 2 이상을 둔다. 두 눈이 있으면 눈빛은 둘 다 왼쪽 위에 둔다(광원이 하나다).

**블랙 스팟과 명도**

### 3.2 백환 관리자 `reliquary`: 지운 선을 거두는 관리인 (2장 · rings)

**게임 근거(확인).** 2.35초마다 0.44초 예고(보스 둘레 링, `enemy.radius × 1.9`, `GameEngine.ts:3698`) 뒤 22발 방사탄을 쏜다('ring' 종류, `:3895–3898`).

**칭호를 형태로.** 지워진 선을 고리에 꿰어 함에 모은다. 고리 세 개가 함을 광배처럼 감싼다. art에서는 고리마다 거둔 선 조각 2~3개(paper300 짧은 가는 획)를 매단다.

**실루엣(48px)**
- 40° 넘게 굽힌 작은 몸.
- 등에 진, 몸보다 높고 지붕이 뾰족한 첨탑 함.
- 함 윗부분을 감싼 고리 셋.
- 판독 포인트는 "고리 두른 등짐"이다.
- 종탑 간수(범종 머리, 열쇠 지팡이)와는 발사원이 고리라는 점으로 갈린다.

**형태 언어.** 뾰족 아치와 원(고리). 몸은 C자 곡선이다.

**블랙 스팟과 명도**

**소품**

- 일식 원장(중간 보스: 머리 뒤 일식 광배, 연미복)과는 광배가 없고 법복이 닫혀 있다는 점으로 갈린다.
- 모자 뒤 아래에 접힌 짧은 날개 한 쌍(사모 변형)은 선택이다. 붙이면 모자 폭의 0.4배 이하로.

**형태 언어.** 세로 기둥과 원통, 가로 실 땀, 지워진 물림.

**블랙 스팟과 명도**
- 다섯 중 가장 어두운 몸이다. 법복은 먹 기둥 하나이고 망점이 없다.
- 법복 위에 흑요 반사 ink500 초승달 2~3개(왼쪽 위를 향함).
- 모자는 ink에 왼쪽 ink500 세로 띠, 윗면은 ink700 타원.

**재질**
- 모자 띠는 paper300 가는 띠이고 흰 실 땀 3개를 박는다(입과 짝을 이룬다).
- 목에 흰 깃(paper300)을 좁게, 먹테 6.
- 의사봉 머리는 ink700에 ink500 띠 둘, 자루는 ink.
- 붓(준비 자세): 대나무 자루 ink300, 붓털 paper300.
- 5장 지워진 가장자리: 법복 옷단에 투명 물림 2곳(먼 소매에 1곳은 선택). 굵은 먹테를 몸 알파로 가린다(bossesB `holes`·`rims`, `k-bosses2.js:892–901`).

**얼굴.** 머리 중심 (202, 170), ρ 18, 두개골 위(모자 띠 아래) 150, 턱 190, `wrap` yaw 30°, 5° 숙임.
- 종이 가면: 판결문 백지(paper)가 얼굴을 원통으로 감싼다(phi −70° ~ +60°).
  - 윗변은 모자 띠 아래로 들어간다. 아랫변은 턱선에서 찢긴 톱니다. 가까운 옆변은 검은 두건(coif)과 머리카락 속으로 들어간다.
  - 이 먹 테두리(모자, 두건, 깃)가 액자다. 가면 가장자리 구김 2줄(art).
- 눈: 일식 고리 둘. 먹 바깥 고리 → paper50 가는 고리 → 먹 원(홍채).
  - 가까운 눈 phi −28°, art r 4.5, game r 6(검은 원 r 3 이상).
  - 먼 눈 phi +28°, 가로 ×0.53. 안쪽 끝을 콧등이 살짝 가린다.
  - 눈빛 paper50 점은 두 눈 모두 홍채 왼쪽 위.
- 눈썹: 굵은 먹 붓선. 코 쪽 끝이 두껍고 아래로 기운다(엄함). 먼 눈썹은 짧다.
- 코: art에서 콧등 담묵 한 획과, 코끝 아래 가까운 쪽으로 먹 콧방울 쐐기. 코끝은 먼 윤곽 안쪽에 둔다.
- 입: 중심선에 걸친 먹 띠(두께 art 2.5~3, game 4, 길이 12~14, 양끝이 살짝 처진다) 위로 paper50 X 실 땀이 가로지른다(art 5, game 3). 땀 간격은 `wrap`의 k를 따라 먼 쪽이 촘촘하다.
- 그림자: 먼 볼 면 세로 띠 하나(관자놀이 → 턱. game paper300 평면, art 20~40% 망점) + 코 밑 쐐기. 모자에 챙이 없으므로 눈 위 그림자 띠는 없다.

**상태**

| pose | 몸 | 소품·효과 |
|---|---|---|
| idle | 곧게 섬 | 가까운 손(화면 왼쪽)이 가슴 앞에 의사봉을 머리 위로 들고, 붓은 먼 소매 속에서 자루 끝만 보인다 |
| windup | 몸을 먼 쪽으로 틀며 먼 팔을 높이 든다 | 붓을 거꾸로(붓털이 위로) 들고 머리 위를 크게 쓸어 지운다. 붓털에서 시작해 머리 위를 지나는 **지운 자국 호**(폭 14, voidPaper 평면 + 담묵 점선 가장자리, `front`)가 바닥 null 지대(무늬가 지워진 평면)를 미리 보여 준다. 호박은 '!' 말고 쓰지 않는다. 의사봉은 허리 뒤로. '!'는 지운 호와 겹치지 않는 `head` windup에 |
| attack | 가까운 팔을 내려친다 | 의사봉이 아무것도 없는 허공을 내려친다(호 아래 끝 약 (250, 250)). 둘레에 **지워진 음파** 호 3개(voidPaper 띠 6 + 담묵 점선, `front`). 먹 소리선이 아니라 소리가 지워졌다는 뜻이다 |
| death 0 | 반동 | 입의 실 땀 하나가 끊어져 입이 조금 벌어지고 모자가 기운다 |
| death 1 | 무릎 | 모자가 뒤로 떨어지고 의사봉을 놓친다 |
| death 2 | 법복이 퍼진 먹 더미 | 종이 가면이 더미 위에 |
| death 3 | 웅덩이: (192, 328), rx 96~106, ry 40~45 | 옆으로 누운 원통 모자, 의사봉, 위를 본 종이 가면(실 땀이 끊겼다), 웅덩이에 투명 물림 1~2 |

- (선택) 페이즈 2: 입의 실 땀 하나가 끊어짐 + 모자 띠를 가로지르는 종이 금.
- 앵커 시작값
  - face (206, 170), faceBox [184, 150, 40, 44]
  - head: idle (204, 98), windup (232, 70)
  - muzzle = 의사봉 머리: idle (240, 212), attack (250, 250). brush windup (276, 92)
  - portrait { center [204, 164], scale 0.22 }

## 4. 선택 과제 (필수 항목이 합격한 뒤에)

`PN.fieldBosses.fx.*`는 짝 보스와 예고 도형을 가르는 참고 그림이다.
- 렌더러는 지금 지형과 예고를 캔버스로 그린다(`docs/art/pipeline.md` 위험지형 절). 그래서 이 그림은 메인 세션이 캔버스 코드를 고칠 때 보는 디자인이다.
- 소속 문법(§12.2)과 샌드위치 규칙을 지킨다.
  - preview: 2px 붓 점선 + 호박 성긴 해칭
  - imminent: 5px 테 + 조밀 해칭 + 눈금
  - active: 산호 α0.55 + 먹 망점 가장자리

| 함수 | 그림 | 갈라 보이는 짝 |
|---|---|---|
| `shockCracks(x, y, r, {state, progress})` | 붓 머리가 중심에서 r까지 그려 나가는 방사 균열 8줄. imminent에서 균열 끝을 원으로 잇고, active는 산호 채움 | — |
| `ringShot(x, y, r)` | 속이 빈 고리탄: 먹 2 + 산호 테 2.4 + 종이 점, 가운데는 투명 | 종탑 간수의 먹알 탄 |
| `compassSnare(x, y, r, {state, progress})` | 가운데 컴퍼스 바늘 자국 + 붓이 원을 그려 나가는 원형 올가미(안쪽 사슬 기호, 격자·걸쇠 없음) | 걸쇠 여제의 격자 덫 |
| `dialRing(x, y, r, {progress})` | 눈금 12개가 시계 방향으로 차오르는 원(감속장 안쪽 기호) | 시계 폭군의 쓸리는 레인 |

## 5. 작업 순서 (권장)

1. **뼈대**: bossesB 합성기와 도우미를 복사하고 `plane`, `wrap`, BOX, META, ids, anchors, `hitbox`를 만든다. 빈 몸(사각형)으로 `--check` ok를 먼저 받는다.
2. **균열 장교 대기**(art·game)와 얼굴을 그린다. 얼굴 크롭, 초상 모의, 48px 줄로 확인하고 여기서 얼굴 그리는 방법을 굳힌다.
3. 나머지 넷의 대기와 얼굴.
4. 다섯의 준비 자세 → 공격 → 처치 4장. 먹 더미와 웅덩이는 공용 도우미로 만들고 보스별 잔해만 따로 그린다.
5. 측정(§6.5), API 문서, 전체 `--check`.
6. 시간이 남으면 페이즈 2, 그다음 `fx`.

## 6. 합격 기준과 확인 명령

- 명령은 모두 한 줄이다. `--expr`는 작은따옴표로 감싸고 안에서는 큰따옴표만 쓴다(훅 규칙). `<id>` 자리를 바꿔 넣는다.
- 다른 작업자의 새 모듈(`k-bosses3.js` 등)이 작업 중 오류를 내면 `--check`가 "kit error"로 실패할 수 있다. 그 오류가 자기 모듈 것이 아니면 납품서에 적고, 자기 그림의 `ok` 줄을 따로 적는다.
- 아래 표현식 틀은 기존 보스로 바꿔 돌려서 문법과 `--check` 통과를 확인했다(2026-10-02).

### 6.1 전체 검사: 실패 0건

```
node scripts/art-review-sheet.mjs expr --name fb-all --scale 0.25 --check --expr '["commander","reliquary","architect","executioner","judge"].map(function(id,j){return ["idle","windup","attack","d0","d1","d2","d3"].map(function(s,i){return ["art","game"].map(function(d,k){var o={detail:d};if(s=="windup")o.windup=true;else if(s=="attack")o.pose="attack";else if(s!="idle"){o.pose="death";o.frame=+s.slice(1)}return "<g transform=\"translate("+(i*400)+" "+((j*2+k)*400)+")\">"+PN.fieldBosses.draw(id,o)+"</g>"}).join("")}).join("")}).join("")'
```

같은 명령에서 `var o={detail:d};`를 `var o={detail:d,mono:true};`로 바꿔 단색도 검사한다(`--name fb-all-mono`). 페이즈 2를 그렸다면 `o.phase=2`로도 검사한다.

얼굴 합격 기준(§2):
- **한 시점**: 판 위 모든 요소(눈금, 구멍, 눈, 금, 실 땀, 유리 반사)가 판과 같은 비율로 눌려 있다. 먼 쪽 요소는 좁고 촘촘하다. 정면 정원, 좌우 대칭 눈, 프로필 윤곽이 없다.
- 평평한 판은 두께 띠가 왼쪽에만 보인다. 감은 가면은 가로선이 아래로 볼록하다.
- 그림자는 덩어리 하나와 액센트 하나이고 경계가 곡선이다. 직선 다각형과 수평 띠가 없다.
- 선 위계: 외곽 > 판 테 > 이목구비 > 금·눈금.
- 0.5배에서 밝은 초점이 3px 이상이고 먹 여백이 1px 이상이다. 84px 초상에서 §2.5의 초상 디테일이 보인다.
- 얼굴판 면적이 보스 면적의 12% 이하다(근사. 어떻게 셌는지 적는다).

### 6.5 측정 (API 문서에 표로 적는다)

```
node scripts/art-review-sheet.mjs expr --name fb-<id>-bbox --scale 1 --check --expr '(function(id,o){var m=PN.fieldBosses.draw(id,Object.assign({detail:"game",shadow:false},o)),s=document.createElementNS("http://www.w3.org/2000/svg","svg");s.innerHTML=m;document.body.appendChild(s);var b=s.getBBox();s.remove();return m+"<text x=\""+Math.round(b.x)+"\" y=\""+Math.round(b.y-8)+"\" font-size=\"16\" font-family=\"monospace\" fill=\"#0E0E10\">"+[b.x,b.y,b.width,b.height].map(Math.round).join(",")+"</text>"})("<id>",{windup:true})'
```

- 그림 위에 범위 `x,y,w,h`가 찍힌다. 이 `<text>`는 검수 그림에만 들어가고 모듈 출력에는 넣지 않는다.
- 투명한 도형도 범위에 들어가니 쓰지 않는 투명 도형은 남기지 않는다.
- pose마다 범위, 키(px), 폭을 적는다. 메인 세션이 이 값으로 아틀라스 칸 여백을 정한다.

### 6.7 소속과 금지 (자기 파일을 읽어 확인)

## 9. 열린 질문

1. **장교가 예고 중에 미끄러진다.** 균열 장교는 0.52초 예고 동안에도 계속 쫓아온다. 이동 코드에 shock 정지 분기가 없다(`GameEngine.ts:3312–3324`, 확인). 그래서 군도를 땅에 꽂은 그림이 약 50 유닛(속도 92 × 0.52초) 미끄러진다.
   - remaster 규칙에 "예고 동안 정지" 플래그를 둘지, 그냥 둘지 정해야 한다.
   - 플래그를 두면 시드 결과가 바뀌므로 규칙 플래그와 밸런스 확인이 필요하다.
2. **초상 디테일.** 필드 보스 초상을 `detail: 'art'`로 구울지 정해야 한다.
   - 필드 보스는 초상 배율이 커서(k ≈ 1.5) game 외곽선이 초상에서 약 6 CSS px로 두꺼워진다. 라운드 보스 초상은 game이다.
   - 검수 때 두 모의 초상을 비교해 정한다.
3. **광폭화.** 필드 보스가 광폭화 상태로 보일 일이 있는지 확인이 필요하다.
   - (추정) 광폭화는 보스 스테이지 시계가 끝날 때 켜지고, 그 시계는 캠페인에서만 줄어든다(`GameEngine.ts:1952`). 필드 보스는 일반 스테이지에 나오므로 볼 일이 거의 없다.
   - 있다면 4순위로 추가한다.
4. **고리탄 모양.** 백환 관리자의 "속이 빈 고리탄"(로어 §4.1)은 지금 종탑 간수 탄과 같은 모양이 된다. 렌더러가 탄을 종류(`'ring'`)로만 그리기 때문이다(`visualRegistry.ts:210–216`). 보스마다 탄 모양을 따로 둘지 정해야 한다.
5. **심판관 모자.** 사모 날개를 붙일지 정해야 한다. 기본은 날개 없는 원통이다.
