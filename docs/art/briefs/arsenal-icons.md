## 1. 공통 계약

### 1.1 모듈·로드·이름공간
- 파일 이름은 실행서대로 `k-icons2.js`다. 무기 전용 모듈이라 이름공간은 `window.PN.arsenal`이다. 모든 선언은 IIFE 안에 둔다(`window.PN = window.PN || {}`).
- 로드 순서는 `lib.js` → `k-icons.js` → `k-icons2.js`다.
  - 리뷰 시트는 굽기 순서 다음에 나머지를 이름순으로 읽는다(`scripts/art-review-sheet.mjs:30-31`). 그래서 따로 할 일이 없다.
  - 굽기 두 곳에는 메인 세션이 넣는다(§7).
- **써도 되는 것**
  - `PN.icons.skill`·`tile`·`hudSlot`. §1.3 방식으로만 부른다.
  - `PN.icons.K`
  - `PN._ki`의 도우미(읽기만): `S`·`P`·`L`·`T`·`f`·`rng`·`poly`·`taperPoly`·`taperFn`·`bw`·`smooth`·`burst`·`ellipsePts`·`blob`·`drip`·`inkDot`·`slimNeedle`·`enso`·`crescent`
  - `PN.taper`·`PN.rng`·`PN.splat`
- **부르지 않는 것**: `PN.skillVfx`·`PN.heroKit`·`PN.enemies`·`PN.env`·`PN.vfx`·보스 모듈. 리뷰 명령에서는 불러도 된다.
- **고치지 않는 것**: `PN.icons`와 `PN._ki`의 값을 바꾸거나 더하지 않는다. 예외는 §1.3의 '호출 동안만 빌리기' 하나다.
- **id**
  - 탄 조각과 리뷰 도우미는 `k-icons.js:28-62`의 `ctx`를 복사한 자기 `ctx`를 쓰고, 접두는 `kar<N>_`다.
  - 아이콘·타일·슬롯의 id는 빌린 `PN.icons`가 `ki<N>`로 매긴다.
- **결정성**: `Math.random`·`Date`를 쓰지 않는다. 들쭉날쭉한 값은 `PN._ki.rng(seed)`로 만든다.
- **글자**: 아이콘과 탄에 `<text>`를 넣지 않는다. 각성 타일의 覺 낙관은 틀이 그리는 기존 문법이다(§9 Q4).
- **한글**: `META`의 이름·설명은 API 문서용이다. `parts()` 서술자에는 `window` 말고 한글을 넣지 않는다. 굽기가 이 서술자를 매니페스트로 옮긴다(`build-atlas.mjs:153-160`).

### 1.3 틀 빌리기 (정확히 이 방식)
`PN.icons.skill`·`tile`·`hudSlot`은 `PN._ki.ICON[id]`에서 그림 정의를 찾는다(`k-icons.js:434`, `:525`, `:1135`). 무기 정의는 모듈 안의 자기 표 `DEF`에 두고, **호출하는 동안에만** 빌려 넣었다가 반드시 지운다.
```js
function borrow(id, fn) {
  const ICON = PN._ki.ICON, def = DEF[id];
  if (!def) throw new Error(`unknown arsenal id ${id}`);
  if (Object.prototype.hasOwnProperty.call(ICON, id)) throw new Error(`${id} clashes with a core icon`);
  ICON[id] = def;
  try { return fn(); } finally { delete ICON[id]; }
}
A.skill = (id, o = {}) => borrow(id, () => PN.icons.skill(id, o));
A.tile = (id, o = {}) => borrow(id, () => PN.icons.tile(id, o));
A.hudSlot = (id, o = {}) => borrow(id, () => {
  const skill = PN.icons.skill;   // 각성 슬롯: build-ui-art.mjs:112-121과 같은 방식
  if (o.awakened) PN.icons.skill = (i, q) => skill(i, { ...q, awakened: true });
  try { return PN.icons.hudSlot(id, o); } finally { PN.icons.skill = skill; }
});
```
- `DEF[id]`의 꼴은 `{ rarity, kind: 'active', name, draw(c, A) → { bg, fg, top }, halo? }`이다(핵심 아이콘과 같다).
  - `rarity`는 `arsenal.ts`의 값이다.
  - `c`는 빌린 `PN.icons.skill`이 넘기는 ctx다. 망점 하한(`c.minPitch`)이 걸려 있다.
- **아직 안 그린 무기**(나눠 납품하는 동안)
  - `META[id].done = false`로 둔다.
  - `draw`는 그 look의 핵심 그림 `PN._ki.ICON[look].draw(c, A)`를 그대로 돌려준다(읽기만).
  - 탄 `stamp`는 §4.2 규격을 지키는 단순한 종이 바늘 자리표시를 돌려준다.
  - 그러면 모든 명령이 납품마다 돈다. 메인 세션은 `done`인 것만 등록한다.

### 1.4 META 필드

| 필드 | 내용 |
|---|---|

  - 슬롯: 56×60 CSS, 원점 (−2,−2), `hudSlot(id, {size:40, awakened})`. 레벨 점은 굽기가 지운다. @2x 112×120px
- 무기마다 [평상, 각성] 순서로 88칸이다. 시트를 어떻게 나눌지는 메인 세션이 정한다(§7, §9 Q1).
- 무기는 융합 재료가 아니다(`buildDepth.ts:17-24`). 도감에도 없다. 그래서 96px 융합 칸과 도감 칸은 쓰지 않는다.

### 2.2 아이콘 창 규칙
- **마스터와 빛**: 마스터는 128×128이고 빛은 왼쪽 위에서 온다. `draw(c, A)`는 다음 셋을 돌려준다(`k-icons.js:439-451`과 같은 계약).
  - `bg`: 창 안 바탕(망점·먹 띠·구름·바닥 띠). 각성에서도 창 안에 남는다.
  - `fg`: 주제. 각성에서는 1.1배로 커지고, 창 밖으로 10까지 나가고, 종이 테 2.2가 둘러진다.
  - `top`: 주제 앞에 있으면서 창 안에 남아야 하는 것.
- **바탕**: 평상 바탕(종이 + 오른쪽 아래 망점 + 종이결)과 각성 바탕(먹 + 종이 원상 + 망점 고리)은 빌린 `PN.icons.skill`이 깐다. 그림은 그 위에 얹는다.
- **망점**: `c.dot`·`c.ht`로만 쓴다. 하한은 max(8, 3·128/표시 크기)다(API-icons:23). `PN.halftone`을 직접 부르면 하한을 건너뛰므로 금지한다.
- **블랙 스팟**: 아이콘마다 큰 먹 덩어리 하나를 둔다. 주 덩어리 자체이거나 그 바탕이다. 먹 면적은 창의 15~55%, 종이는 25% 이상을 눈대중으로 맞춘다(추정 기준, 잴 도구 없음).
- **선**
  - 주제 외곽은 `S()`(먹 그림자 사본 + 선 2.2~3.2)다. 내부선은 1~1.8이다.
  - 32px에서 보여야 하는 정보 선은 4 단위(1px) 이상이다.
- **낙관 피할 구역**: 아이콘 좌표 **(94~128, 0~34)**.
  - 여기를 가리는 것은 둘이다. 각성 타일의 覺 낙관(`k-icons.js:513-515`, 렌더 `b3-seal-zone`)과 HUD의 각성 준비 원상 배지다(`styles.css:411-422`). 배지가 덮는 곳은 (105~128, 0~21)이다(계산).
  - 이 구역에 주 덩어리, 개수, 과녁, 모티프 머리를 두지 않는다.
  - 바탕, 꼬리, 속도 획, 긴 선의 일부는 둬도 된다.
- **모서리**: 영웅 이상 틀의 모서리 마름모(`k-icons.js:494-496`)가 창 모서리에서 8까지 들어온다. 네 모서리 10 안에 정보를 두지 않는다.

### 2.3 색과 신호
- **색**: `PN.icons.K`의 ink·ink7·ink5·ink3·ink1·p50·paper·p300·ally·allyD·allyG만 쓴다. 산호·호박·연두·자수정·은니·금니·장 재질색·hanji(틀 전용)·voidp는 0이다(C4).
- **청록**
  - 무기는 모두 액티브다. 청록 **요소 한 가지**를 둔다.
  - 같은 요소가 여러 개인 것은 괜찮다. 핵심 먹선 바늘의 실 셋과 같다(API-icons:26).
  - 무기별 요소는 §3.4에 있다.
  - 청록은 늘 먹 위에 얹는다(먹 ≥ 2 + 청록 + glow 또는 종이 심, 바이블 §5.3).
- **해칭** 0이다(`c.hatch` 금지, 바이블 §6-5). 블러·그라데이션·혼합 모드도 0이다(§6-1·§6-9).

### 2.4 평상과 각성

| | 틀이 하는 것(빌린 `k-icons`) | 그림이 할 것(`draw`의 `A`) |
|---|---|---|
| 타일 평상 | 등급 테(1·2줄, 마름모, 찢긴 가장자리, 은니·금니 띠), 매듭 = 등급 수, 신화는 먹 카드 | 종이 바탕 위의 주제 |
| 타일 각성 | 아래 '타일 각성 틀' 목록 | 아래 '각성 그림' 목록 |
| HUD 슬롯 | 액티브 네모 슬롯 + 매듭(`k-icons.js:1134-1160`). 각성 슬롯은 같은 슬롯에 각성 아이콘을 넣는다 | 타일과 같은 그림 |

**타일 각성 틀**(빌린 `k-icons`가 그린다)
- 같은 등급 테에 먹 번짐 얼룩과 覺 낙관을 더한다.
- 아이콘 바탕은 먹, 그 위에 종이 원상이다.
- 주제는 1.1배로 커지고 창 밖으로 10까지 나가며 종이 테가 둘러진다.
- 매듭 수는 원래 등급 그대로다(API-icons 판정 2).

**각성 그림**(그림이 `A`로 바꾼다)
- 수가 있는 kind는 요약의 수 + 1을 그린다. 8 이상이면 2~4개를 더해 '더 빽빽'하게 보인다.
- 고리·띠·폭은 1.2배다(`arsenal.ts:102` 각성: 피해 1.35배, 수 +1, 범위 1.2배, `ko.json:858`).
- bg의 망점은 뺀다. 큰 먹 면은 ink7, bg의 먹 선은 p300으로 바꾼다. 핵심 아이콘과 같은 규칙이다(예: `k-icons.js:212-222`).

### 3.3 과녁 먹귀·결 매듭·얼굴
- **과녁 먹귀**
  - `PN._ki.inkDot(c, x, y, r, seed)`를 그대로 쓴다. 1장 종이 슬릿 눈이다.
  - 주 과녁은 r ≥ 12, 먼 과녁은 r ≥ 7이다.
  - 한 호출 안에서 seed를 겹치지 않는다. `c.clip('dl'+seed)` id가 겹친다.
  - 같은 크기의 먹귀 둘을 같은 높이에 나란히 두지 않는다.
- **결 매듭(結)**
  - 주인공이 있는 자리를 뜻한다. rear 셋, 먹 파동, 십자 획, 수호 고리에 쓴다.
  - 종이 매듭(지름 12~16, 고리 둘과 끝 둘이 보임)에 먹 테 2.4를 두른다.
  - 카드 아래 등급 매듭(먹 원)과 꼴이 달라야 한다. 속이 종이고 고리가 보여야 한다.
- **얼굴**: 이 발주에 사람 얼굴은 없다. 얼굴처럼 보이는 곳은 아래 셋뿐이다.
  - 먹귀의 슬릿 눈(그대로 쓴다)
  - 보스 사냥침의 보스 가면
    - 3/4 한 시점으로 그린다. 가면 윤곽 + 눈 구멍 둘(먼 눈은 가까운 눈 폭의 0.6) + 굵은 먹테 + 흰 눈빛이다.
    - 코와 입은 그리지 않는다. 가면 면적은 아이콘의 12% 이하다.
    - 정면 두 눈을 옆모습 몸에 올리는 섞인 시점(R4 입체파 실수)은 금지다.
  - 천둥 박수의 손: 얼굴이 없다.

## 4. 탄 모양

### 4.1 범위 (확인)
- 투사체가 있는 kind만 해당한다. volley·burst·spray·rear·seeker 5종, 무기 22개다. 이들만 `spawnProjectile`로 `Projectile`을 만든다(`GameEngine.ts:2403`).
- strike·nova·lob·chain·beam·halo는 투사체가 없어 범위 밖이다(§9 Q2·Q3).
- 렌더러는 지금 `shot.look`으로 조각 그룹을 고르고, 각성은 무기 자신을 본다(`worldRenderer.ts:1359`·`:1362`). 메인 세션이 무기 자신의 그룹을 고르게 바꾼다(§7).
- 탄은 그 무기 아이콘의 모티프와 **같은 물건**이다. 작아졌을 뿐이다.

### 4.2 조각 규격
- **조각 이름**: `start` · `travel` · `end` · `start-awakened` · `travel-awakened` · `end-awakened`. 각 2장이다.
- **구동**은 K4 탄과 같다(API-skills-vfx §5·§7).

  | 조각 | drive | 시간 |
  |---|---|---|
  | start | prog | 나이 0~0.06초 |
  | travel | loop 12fps, still 0 | — |
  | end | prog | 남은 수명 0.10→0초. 수명이 다할 때만 쓴다 |

  이름이 같아서 굽기의 `SKILL_VFX_TIMING`(`atlas-spec.mjs:395-399`)이 그대로 맞는다.
- **나머지 필드**: `rotate: 'vel'`, `layer: 'ally'`, `lod: 'info'`, `flash: false`, `scale: 1`(월드 단위 = 1x px)이다.
- **앵커** = 투사체 좌표 = 판정 원 중심. +x는 속도 방향이다.
- **박스·앵커**(r별). 칠한 모든 기하는 박스 가장자리에서 3 이상 안쪽에 둔다.

  | r | 무기 | 박스 | 앵커 |
  |---|---|---|---|
  | 3.5 | inkDrizzle | 40×18 | (31, 9) |
  | 4 | inkDarts, thornHalo | 46×20 | (35, 10) |
  | 4.5 | frostNeedles, thunderNeedles, headsmanDarts, inkBloom, pinHail, smokeTail, gravePins, trackingSeals | 50×20 | (39, 10) |
  | 5 | brushQuills, ghostVolley, paperStorm, sunNeedles, tailGuard, huntersMarks, crowFeathers | 54×22 | (43, 11) |
  | 5.5 | starShards, bossbane | 60×22 | (47, 11) |
  | 6 | sealArrows, twinBlades | 64×24 | (51, 12) |

- **판정과 그림**(V4, C7이 잰다)
  - 앞끝(칠한 기하의 가장 앞)은 **r − 0.5 ~ r + 2.5**다.
  - 옆은 **r + 2.5 이하**다.
  - 뒤(꼬리 포함)는 **8r 이하**다. 렌더러가 탄을 판정 반경의 8배 원으로 잘라내기 때문이다(`worldRenderer.ts:1336`). 기존 결 바늘 꼬리 38은 이 기준을 넘으므로 새 탄은 더 짧게 그린다.
  - 그림 크기는 판정을 바꾸지 않는다.

### 4.3 공통 그림 규칙
- **색**: K 토큰 11개(ink·ink700·ink500·ink300·ink100·p50·paper·p300·ally·allyD·allyG)만 쓴다. 산호·호박·자수정·연두와 장 재질색은 0이다(C4).
- **몸**
  - 1배 흑백에서 몸의 가장 큰 덩어리가 종이(p50·paper·p300)로 읽힌다(C12). C9의 먹 비율이 65%를 넘으면 다시 본다. 아군은 밝다(P1, 바이블 §12.1). (검수 1차 정정: '칠한 넓이의 40% 이상 종이'는 외곽 1.5를 넣어 재면 기존 K4 탄도 못 맞춘다.)
  - 외곽은 먹 1.5(바이블 §3), 내부선은 0.6~1.0이다.
- **청록**: 무기마다 요소 하나다(§4.4). 늘 먹 위에 얹는다. 실은 [ink 2.6, ally 1.6, allyG 0.5]다. start·travel에는 반드시 청록이 있어야 하고, end에서는 allyD로 어두워져도 된다.
- **꼴**
  - 길쭉하고 앞이 뚜렷해야 한다(길이 ≥ 폭의 2배).
  - 둥근 먹알 + 종이 점은 적 탄 문법이라 금지다(바이블 §12.3).
  - 화살촉은 버들잎 꼴이다(삼각 금지).
- **결 바늘(가는 종이 바늘 + 청록 S자 실)과 닮지 않는다.** 실 꼬리는 trackingSeals(점선 실)와 bossbane(한 번 휜 실)만 쓰고, 둘 다 결 바늘 실과 모양이 달라야 한다.
- **필터 금지**: 필터(거친 선 포함), 종이결, 그라데이션, 블러, 혼합 모드는 0이다. clipPath·mask·묶음 opacity만 쓴다.
- **장마다 할 일**

  | 조각 | 0번 장 | 1번 장 |
  |---|---|---|
  | start | 꼬리 30% | 꼬리 70% |
  | travel | 흔들림 하나(실 위상·회전·펄럭임) | 0번 장과 위상이 다름 |
  | end | 꼬리가 처지거나 풀리고, 청록은 allyD | 몸은 p300, 외곽은 ink300, 묶음 α 0.6 |

- **각성**(세 조각 모두): 몸과 청록 요소는 그대로 두고 아래만 더한다.
  - 몸 둘레에 겹 테를 두른다(종이 1.0 + 먹 0.8). 앞끝 3 단위는 비워서 앞끝이 늘지 않게 한다.
  - travel 0번 장에서 앞끝 **위쪽**에 5~6갈래 불규칙 종이 반짝임(r 2.2~2.8)을 둔다.
  - 꼬리가 있으면 1.25배로 늘린다(8r 안).

- 아군과 적: 1배 색·흑백에서 모든 탄이 '밝은 몸 + 청록'으로 읽혀야 한다. '어두운 알 + 산호 테'(적 탄)로 읽히면 안 된다(C8).

## 5. 합격 기준

### 5.1 구별 시험
- **T1 · 같은 look 묶음**(`k9-t1-looks`): look마다 한 줄이다. 핵심 아이콘(점선 칸)과 무기를 32px 색, 32px 흑백, 20px 흑백으로 놓는다.
  - 합격: 각 줄에서 어느 두 칸도 헷갈리지 않는다. 핵심 아이콘은 모든 무기와 갈린다.
  - 꼭 볼 줄: needleStorm(14칸), fanKnives(7), boneMortar(7), chainSpark(6).
- **T2 · 같은 kind 묶음**(`k9-t2-kinds`): 평상판과 각성판을 둘 다 본다.
  - 합격: 32px 흑백에서 모두 갈리고, 20px 흑백에서 §3.4의 '주 덩어리'가 서로 다르다.
  - 꼭 볼 묶음: burst의 흰 방사 셋(종이 폭풍·별조각·해바늘), beam의 수평 둘(먹창·넓은 붓), halo의 흰 타원 둘(수호 고리·일식 테).
- **T3 · 이름 없이 섞은 20px 흑백**(`k9-t3-blind20` + `k9-t3-key`)
  - 합격: 검수자가 §3.4 표만 보고 44종 중 40종 이상을 맞힌다.
  - 헷갈린 쌍은 납품서에 적고 고친다.
  - 정식 판독 시험(n ≥ 8)은 통합 뒤에 팀이 한다.
- **T4 · 탄**: 합격 조건은 §4.5다. C6을 1배와 6배로, C8을 1배·0.8배·흑백으로 본다.
- **T5 · 금지 모양**: 120·32·20px에서 §2.6에 해당하는 것이 0이다.
- **T6 · 낙관 구역**: C2의 평상 타일에 겹친 산호 점선 네모 안에 주 덩어리·개수·과녁·모티프 머리가 없다. 각성 타일에서 낙관이 바탕만 가린다.

## 11. 검수 정정 (2026-10-16, 검수 4차)

검수 4차(`docs/art/deliveries/K9-arsenal-icons.md`)가 제안한 정정이다. 3차 납품과 2차 수정에 적용한다.

1. **§3.1 burst**: 모티프가 6개 이하이면 회전 규칙성을 깬다. 가장 큰 사이각이 가장 작은 것의 1.6배 이상이고, 거리 차가 20% 이상이어야 한다. 무기별 '정칙 별 금지'가 ±6° 틀보다 앞선다.
2. **§4.5 같은 계열의 탄**: 같은 look을 쓰는 무기의 탄은 1배에서 서로 다른 물건으로 읽혀야 한다(사용자 2026-10-15). 검사 C13으로 look 계열별 1배 확대 탄 시트를 더한다.
3. **§3.2 효과 표지 먹귀**: 눈이 보여야 한다. 먹·연기·타르에는 발만 잠긴다.
4. **§5.1 T3**: 에이전트 검수자에게는 20px 정보량을 픽셀 블록으로 확대한 블라인드 시험을 보조 도구로 쓴다(검수 4차 §7의 `k9-t3px-blind20` 명령, 시드를 바꿔 쓴다). 사람 판독 시험(n ≥ 8)은 그대로다.
5. **보존 해시**: 무기 목록을 고정한 식으로 잰다. C9의 crop은 `0,0,1400,1080`이다.
6. **각성 그림과 SYS-16**(검수 4차 §8 열린 질문, 메인 세션 결정): SYS-16(`docs/decisions/SYS-16-awakening-gimmicks.md`)으로 무기마다 각성 기믹이 다르지만, 각성 타일·슬롯 88칸은 §2.4대로 둔다(수 +1, 범위 1.2배, 覺 낙관). 기믹은 카드 문구가 설명하고, 전장에서 보이는 기믹 그림(땅 조각, 표식, 갈래·메아리 등)은 K10 무기 전장 효과 발주에 넣는다. 이미 그린 22종을 다시 그리지 않기 위해서다.
